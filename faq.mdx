---

<Accordions type="multiple">
<Accordion title="Do I need to know PostgreSQL?">

No. Answer a few questions at install; then backups, Proof and monitoring run by itself. Problems come in plain words, most with an **Apply fix** button. Restores are buttons too: try [Your first restore](/docs/first-restore). Terms: [Glossary](/docs/glossary).

</Accordion>
<Accordion title="What are Rewind, Proof, Pulse and Guard?">

- **Rewind**: restore to any second, or to a **Mark** (a named restore point). [Restore a database](/docs/guides/restore).
- **Proof**: a weekly automatic restore test. [Proof](/docs/concepts/restore-drills).
- **Pulse**: health score, alerts, slow queries, weekly email. [Pulse](/docs/guides/monitoring).
- **Guard**: the safety net for AI agents. [Guard](/docs/guides/ai-agents).

</Accordion>
<Accordion title="What happens if I delete rows by mistake?">

You get them back while production keeps running: **Rewind** → [Find the moment](/docs/guides/find-the-moment), **Restore a copy** from just before, compare, **bring back** the missing rows. Newer rows stay. Default reach: about two weeks back, to the second. [Restore a database](/docs/guides/restore).

</Accordion>
<Accordion title="What if I use an AI coding agent?">

Set up [Guard](/docs/guides/ai-agents). The agent checks the database can be restored and sets a **Mark** before risky changes. It can also [preview a migration](/docs/guides/preview-migrations) or test on a masked [safe copy](/docs/guides/safe-copies).

It acts as the person who connected it, with their rights, like a personal access token. An owner's or admin's agent acts right away, with a Mark first; others are refused with a reason. For a look-only agent, connect it without **Act for you** or use a read-only key. [How AI agents act](/docs/guides/agent-autonomy).

</Accordion>
<Accordion title="Can Rowsafe read my data?">

No. Backups are encrypted on your server; the passphrase and bucket keys never leave it. Rowsafe stores only names, sizes, settings, task logs and metrics. [Security model](/docs/security).

</Accordion>
<Accordion title="Does it slow down my database?">

Barely:

- **Monitoring**: one short local session a minute, cheap queries with a 2-second timeout. [What the agent collects](/docs/guides/monitoring#what-the-agent-collects).
- **Saving changes** copies files PostgreSQL already wrote.
- **Backups, Proof and copies** run at low CPU and IO priority.
- **The agent** gets at most half the default CPU and IO weight, and is stopped before PostgreSQL if memory runs out.

Proof and copies need free disk: about 1.3 × the database size + 1 GB.

</Accordion>
<Accordion title="Does Rowsafe ever restart my database?">

Never on its own. Setup needs one restart (a few seconds); do it at install or later, and Rowsafe notices.

If you allowed it at install, admins (or their AI agents) can restart or [rewind the whole database](/docs/guides/restore#rewind-the-whole-database) from the dashboard, always with a confirmation.

Only two things act without a click, both off until you turn them on: [automatic minor updates](/docs/guides/updates#minor-updates) (Sundays 03:00 your time) and [automatic failover](/docs/guides/standby#automatic-failover).

</Accordion>
<Accordion title="Which databases are supported?">

Servers: Debian 12/13 and Ubuntu 22.04/24.04 (PostgreSQL on amd64 or arm64). Each guide lists its limits.

| Engine | Versions | Docker | Main limits |
|---|---|---|---|
| [PostgreSQL](/docs/quickstart) | 13 to 18 | Official images 14 to 18 | |
| [MySQL, MariaDB](/docs/guides/mysql) | MySQL 8.0, 8.4; MariaDB 10.6, 10.11, 11.4 | Yes | |
| [MongoDB](/docs/guides/mongodb) | 6.0, 7.0, 8.0 | Yes | Replica sets only (one member is enough), no sharded clusters; no pooling |
| [ClickHouse](/docs/guides/clickhouse) | 24.8+ | Official images 25.8 to 26.8 | Single servers |
| [Redis, Valkey](/docs/guides/redis) | Redis 7.0+, Valkey 7.2+ | Yes | Standalone (with or without replicas), no Cluster or Sentinel; Ubuntu 22.04 needs Redis's own packages; no pooling or migration previews |
| [SQLite](/docs/guides/sqlite) | 3 | Volumes (agent as sidecar) | Local disk; any second only in WAL mode; no restart, standby, pooling, server updates, users, logs or tuning; no move-in from Turso or D1 yet |
| [OpenSearch](/docs/guides/opensearch) | 2, 3 | Not yet | One node; snapshots every 5 minutes, not any second; no updates, standby, pooling, tuning or logs |

| [Meilisearch](/docs/guides/meilisearch) | 1.12+ (Community) | Not yet | One instance; snapshots every 15 minutes when changed, not any second; no updates, standby, pooling, tuning or logs |

</Accordion>
<Accordion title="How does Rowsafe back up Redis or Valkey?">

The agent connects like a replica: Redis sends a full snapshot, then every change. Changes upload about every minute, encrypted, so you can restore to about a second or exactly to a Mark. If replication isn't allowed for Rowsafe's user (or `min-replicas-to-write` is set), you get scheduled snapshots only, and the dashboard says so. [How Redis and Valkey backups work](/docs/concepts/redis).

</Accordion>
<Accordion title="Does Rowsafe slow down my SQLite app?">

Barely. It uses SQLite's own locking and online backup API, holding the write lock for milliseconds. In WAL mode your writes never wait for its reads. Only rewinding the whole file (seconds) and **Give free space back** make writes wait. [Safe next to your app](/docs/guides/sqlite#safe-next-to-your-app).

</Accordion>
<Accordion title="Does Rowsafe change my SQLite file?">

Not on its own. Backups only read it, then checkpoint the `-wal` file as SQLite would anyway. Everything else waits for a click and confirmation. At install, root grants the agent access (ACL or group) and prints what changed; the file's owner never changes.

</Accordion>
<Accordion title="Does my SQLite database need WAL mode?">

For restore to any second and Marks, yes. Without it, you get a daily full backup. Pulse offers **Turn on continuous backups** to switch; your app keeps working. [How SQLite backups work](/docs/concepts/sqlite#every-change-in-wal-mode).

</Accordion>
<Accordion title="My SQLite file is in a Docker volume. Does that work?">

Yes. The installer on the host finds files containers have open, or run the agent as a sidecar. [Protect SQLite](/docs/guides/sqlite#docker).

</Accordion>
<Accordion title="Can Rowsafe protect a SQLite file on a network drive?">

No. NFS, SMB/CIFS, sshfs and similar have unreliable locks. Keep the file on local disk.

</Accordion>
<Accordion title="What counts as a database?">

One server instance on one host and port (for PostgreSQL, a cluster), with every database inside it. For SQLite, one file.

</Accordion>
<Accordion title="Which storage can I use?">

Any S3-compatible bucket you own: Cloudflare R2 (first 10 GB free), Backblaze B2, Amazon S3, Wasabi, DigitalOcean Spaces, MinIO. Your provider bills you, not Rowsafe. [Set up backup storage](/docs/guides/storage).

Or [Rowsafe Storage](/docs/guides/rowsafe-storage): nothing to set up, 10 GB on Free, 250 GB on Pro, 2 TB on Business. Still encrypted on your server.

</Accordion>
<Accordion title="How much data can I lose?">

At most about a minute of changes (`archive_timeout = 60`). A nightly `pg_dump` can lose 24 hours. Older setups archive every 5 minutes; **Apply fix** changes that without a restart.

</Accordion>
<Accordion title="How far back can I restore?">

About two weeks by default (2 full backups kept). Change it in the database's settings or with `rowsafe set NAME --retention-full N`.

</Accordion>
<Accordion title="Does Rowsafe restore for me?">

Yes, in one click on the **Rewind** tab: **restore a copy** and bring back rows while production runs, or **rewind the whole database** (undo for 7 days). [Restore a database](/docs/guides/restore).

Limits: bringing back rows needs a primary key; a whole rewind in Docker needs the [container control service](/docs/guides/docker#let-rowsafe-restart-the-container); a lost server is restored by hand with pgBackRest.

</Accordion>
<Accordion title="What if I lose the encryption passphrase?">

Nobody can restore those backups, Rowsafe included. Store it in your secret manager and a second place before the first backup.

</Accordion>
<Accordion title="What happens if Rowsafe is down?">

PostgreSQL keeps archiving to your bucket, so restore to any second still works. Backups, Proof and alerts resume when it's back.

</Accordion>
<Accordion title="What happens if the agent stops?">

PostgreSQL keeps archiving. Backups, Proof and metrics pause. `agent_offline` alerts after 5 minutes; not protected after 10.

</Accordion>
<Accordion title="Can I keep my existing backups?">

Yes, for 30 days: four passing Proof runs and one restore of your own, then retire the old job.

</Accordion>
<Accordion title="Does it do replicas and failover?">

Yes. For PostgreSQL, a [standby](/docs/guides/standby) is kept in sync, readable, and promotable by hand or automatically (off by default). One per database, Linux with systemd, agent installed natively. Adopt the primary; a standby can't be adopted alone. Redis and Valkey standbys are real replicas ([Redis and Valkey](/docs/guides/standby#redis-and-valkey)).

</Accordion>
<Accordion title="Is it open source?">

What runs on your servers is: agent, CLI (with MCP server and Claude Code plugin) and installer, Apache-2.0 on [GitHub](https://github.com/rowsafe/rowsafe). These [docs](https://github.com/rowsafe/docs) are CC BY 4.0. The hosted service and dashboard are proprietary.
