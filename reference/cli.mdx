The `rowsafe` CLI talks to the Rowsafe API. It runs on macOS and Linux (Intel/AMD and ARM).

## Install

No `sudo` needed:

```sh
curl -fsSL https://rowsafe.sh/cli | sh
rowsafe login
```

The script downloads the latest [release](https://github.com/rowsafe/rowsafe/releases) for your computer (native on Apple silicon, even from a Rosetta terminal) and checks it against `SHA256SUMS`. It installs to `/usr/local/bin` if you can write there, else to `~/.local/bin`, which it adds to your `PATH` (open a new terminal). Nothing else changes. [Read the script](https://github.com/rowsafe/rowsafe/blob/main/scripts/cli.sh).

- **Update**: run the same command again.
- **A specific version**: `curl -fsSL https://rowsafe.sh/cli | ROWSAFE_VERSION=0.10.12 sh`.
- **Another folder**: `ROWSAFE_INSTALL_DIR=~/bin`. `ROWSAFE_NO_MODIFY_PATH=1` leaves your shell profile alone.
- **Uninstall**: `rowsafe logout` (revokes its key), then `rm "$(command -v rowsafe)"`.
- **Windows**: use WSL.

## Help

```sh
rowsafe help            # the short overview
rowsafe help all        # every command
rowsafe help COMMAND    # one command, e.g. rowsafe help mark
rowsafe version
```

Flags go before or after the arguments, with one or two dashes (`-yes` or `--yes`).

## Database names

`[NAME]` is found in this order:

1. the `NAME` argument;
2. `ROWSAFE_DATABASE`;
3. `"database"` in the nearest [`.rowsafe.json`](#rowsafejson) (this directory or a parent);
4. your organization's only database.

`NAME` can also be the database's ID. `NAME` without brackets is required.

## Account

| Command | What it does |
|---|---|
| `rowsafe login` | Log in with your browser (confirm the code shown). Saves a new API key. |
| `rowsafe login --key rsk_...` | Log in with an existing API key (CI, scripts). |
| `rowsafe login --url URL` | Another API URL. Default `https://api.rowsafe.sh`. |
| `rowsafe logout` | Forget the login and revoke the key `login` created. `--keep-key` keeps it valid. |
| `rowsafe whoami` | API URL, organization, plan and key in use. |
| `rowsafe init [NAME]` | Write `.rowsafe.json` here, so this project uses `NAME`. |
| `rowsafe org` | Plan, limits and usage. |

The login is saved, readable only by you, in `~/.config/rowsafe/config.json` (Linux) or `~/Library/Application Support/rowsafe/config.json` (macOS).

## Databases

| Command | What it does |
|---|---|
| `rowsafe ls` | Your databases. |
| `rowsafe show [NAME]` | One database in detail. |
| `rowsafe status [NAME]` | With a name: is it [protected](/docs/concepts/protection-status)? Without: fleet health. `--json` for details. |
| `rowsafe adopt NAME` | Register an existing database (PostgreSQL, or another engine with `--engine`) and print a read-only plan. The [installer](/docs/reference/agent-configuration#installer) does this for you. |
| `rowsafe plan [NAME]` | Run the read-only plan again. |
| `rowsafe apply [NAME]` | Apply the plan. Never restarts PostgreSQL. |
| `rowsafe verify [NAME]` | Check now that changes reach your bucket (Rowsafe also does it once it notices the restart). Activates the schedules and queues the first full backup. |
| `rowsafe restart NAME` | Restart PostgreSQL: a few seconds, open connections drop. Asks first; `--yes` skips. |

**`restart`** needs a server where install allowed restarts (`can_restart` is `true`, host online), and not Docker. Admins and owners only, never a read-only key, at most once every 2 minutes. A database in `awaiting_restart` then becomes `active` by itself.

**`adopt` flags:**

| Flag | Default | |
|---|---|---|
| `--host HOST` | | Host name or ID. Optional when the organization has one host. |
| `--port N` | `5432` | The engine's port: PostgreSQL `5432` (names the Unix socket), MySQL and MariaDB `3306`, MongoDB `27017`, ClickHouse HTTP `8123`, Redis and Valkey `6379`, Qdrant REST `6333`, Meilisearch `7700`. |
| `--engine ENGINE` | `postgresql` | `mysql` or `mariadb` ([guide](/docs/guides/mysql)), `mongodb` ([guide](/docs/guides/mongodb)), `clickhouse` ([guide](/docs/guides/clickhouse)), `redis` or `valkey` ([guide](/docs/guides/redis)), `qdrant` ([guide](/docs/guides/qdrant)), `meilisearch` ([guide](/docs/guides/meilisearch)). The installer sets up [OpenSearch](/docs/guides/opensearch). |
| `--socket-dir DIR` | `/var/run/postgresql` | PostgreSQL's Unix socket directory. |
| `--retention-full N` | `2` | Full backups to keep, 1 to 52 (MongoDB: `7`, one a day). |
| `--no-wait` | | Don't wait for the plan. |

`NAME`: 2 to 40 characters, lowercase letters, digits and dashes, starting with a letter.

**`apply` flags:** `--yes` skips the confirmation. `--force` replaces an `archive_command` or `archive_library` set by another tool. Use it only if you know what that tool did.

## Databases and users

The databases, users and extensions inside a PostgreSQL server ([guide](/docs/guides/databases-and-users)). `--on NAME` picks the server (default: the [name rules](#database-names)). Changes need an admin's or owner's read-write key.

| Command | What it does |
|---|---|
| `rowsafe db [ls]` | Databases (owner, size, connections, extensions) and users. `--json` for everything. |
| `rowsafe db create DB` | A database owned by a new user of the same name; password shown once. `--owner USER` (an existing user), `--new-owner USER` (name the new one), `--extension EXT` (repeatable), `--locale L`, `--template template0`. |
| `rowsafe db drop DB` | Remove a database and everything in it, after a Mark. You type the name; `--yes` skips. |
| `rowsafe db users` | Users, the databases they can connect to, and how their password is stored. |
| `rowsafe db user add USER --db DB[,DB]` | A new user; `--access read_only`, `read_write` (default) or `owner`. Password shown once. Redis and Valkey: `--keys PATTERN` instead of `--db` (`"*"` for every key). OpenSearch: `--db` takes indices and patterns (`logs-*`). Qdrant: an API key on the `--db` collections (none listed: every collection, for read-only and `owner` keys); `--expires DAYS` (admin keys always expire: 30 days by default, at most 90). Meilisearch: an API key on the `--db` indexes. |
| `rowsafe db user password USER` | A new password, shown once. |
| `rowsafe db user remove USER` | Remove a user; `--reassign-to USER` gets what it owns. Asks first; `--yes` skips. |
| `rowsafe db ext on\|off DB EXTENSION` | Turn an extension on or off in one database. `--allow-untrusted` for extensions that can run programs on the server. `vector`, `postgis` and `timescaledb` are installed first where root allowed PostgreSQL updates ([Extensions](/docs/guides/databases-and-users#pgvector-postgis-and-timescaledb)). `timescaledb` needs `--restart` unless already loaded: Rowsafe saves a Mark, then restarts PostgreSQL once. |

`--host ADDRESS` on `create`, `user add` and `user password` sets the address in the printed connection string (default: the one your apps use). The password is encrypted on your server to a key the CLI makes in memory; Rowsafe only relays ciphertext.

## Connect apps and psql

PostgreSQL only for now. Other engines: make a login or API key with `rowsafe db user add` (or in the dashboard) and use the engine's own client. `--on NAME` picks the server (default: the [name rules](#database-names)).

| Command | What it does |
|---|---|
| `rowsafe env [DATABASE]` | Write the app's own database and login to `.env` as `DATABASE_URL`. `DATABASE` defaults to this directory's name (`my-app` becomes `my_app`). Creates the database, owned by a new user of the same name. `--reset-password` gives an existing user a new password instead (apps using the old one stop connecting; asks first, `--yes` skips). |
| `rowsafe connect [DATABASE\|SERVER]` | Open `psql` as a temporary user, removed when you quit (what it created goes to the database's owner). `--access read_only`, `read_write` or `owner` (default). `--user USER` connects as an existing user (psql asks its password). psql's own options go after `--`. |

**`env` flags:** `--file .env` (the file), `--name DATABASE_URL` (the variable), `--user USER` (the new owner's name), `--extension EXT` (repeatable, new database only), `--force` (replace the variable if the file has it; otherwise nothing changes), `--print` (also print the connection string with its password).

- The password never passes through Rowsafe and is printed only with `--print`. `env` makes it on your computer and sends only its SCRAM verifier. With an older agent, the server makes it and encrypts it for your terminal.
- `env` writes the variable in place (a new file is readable only by you; an existing one keeps its mode). In a git repo it adds the file to `.gitignore`, and warns if git already tracks it.
- `connect` needs `psql` (it says how to install it) and passes the password in psql's environment, never on a command line. On a [Rowsafe Cloud](/docs/guides/rowsafe-cloud) server that doesn't let this computer connect yet, it offers to allow it first (`--yes` without asking).

## Rowsafe Cloud

[Rowsafe Cloud](/docs/guides/rowsafe-cloud) servers, with your login or a read-write key. `NAME` is a server's name or ID, or its database's name; default: the project's database, else the organization's only server. Anything that costs money or deletes asks first; `--yes` confirms in scripts.

| Command | What it does |
|---|---|
| `rowsafe cloud sizes` | Databases and versions, then clouds, regions and sizes: CPUs, memory, disk, hourly price, the most a month costs, and what's sold out now. `--cloud CLOUD`, `--region REGION`, `--json`. |
| `rowsafe cloud create NAME` | A new server with PostgreSQL, MySQL, MariaDB, Valkey, ClickHouse, OpenSearch, Qdrant or Meilisearch, with backups, Proof and Pulse on. Default: the cheapest size free now, PostgreSQL 17, only this computer may connect. Shows size and price and asks first. The first hourly server gives you a link to add a card, once (an owner pays); it's created right after. |
| `rowsafe cloud list` | Servers Rowsafe created: status, size, price, who can connect. `--json`. |
| `rowsafe cloud show [NAME]` | One server: status, size, price, where apps connect, who can connect, whether the backup passphrase is saved. `--json`. |
| `rowsafe cloud wait [NAME]` | Follow a server being created or resized until ready. `--timeout 30m`. |
| `rowsafe cloud resize [NAME] SIZE` | Another size, after a Mark. The database is offline a few minutes while the server restarts; a pair with a standby switches over instead. Disks never shrink. Asks first; `--yes`, `--wait`. |
| `rowsafe cloud allow [NAME] [me\|IP\|CIDR]...` | Let more addresses connect. Default: this computer (`me`). Asks before opening it to everyone. |
| `rowsafe cloud firewall [NAME]` | Who can connect. Change it with `--set A,B` (the whole list), `--add A`, `--remove A` or `--clear` (nobody). Asks before cutting anyone off; `--yes`, `--json`. |
| `rowsafe cloud passphrase [NAME]` | The backup passphrase, encrypted for this terminal only (Rowsafe can't read it). `--file PATH` writes a new file readable only by you. Rowsafe records that it was saved. |
| `rowsafe cloud clone [SOURCE] NAME` | Copy a PostgreSQL database to a new hourly server: as it is now, `--at TIME` or `--mark LABEL`. Default: next to the source, same size (`--cloud`, `--region`, `--size` to choose). `--delete-after 24h` (1 hour to 30 days) has Rowsafe delete it; otherwise it stays until you delete it. Real data, not masked. |
| `rowsafe cloud retry [NAME]` | Set up again a server that failed. `--wait`. |
| `rowsafe cloud delete [NAME]` | Delete the server and its database. You type the name (`--yes` in scripts). Refused until the backup passphrase is saved (clones aside). `--with-standby` deletes its standby too; `--wait`. |

**`create` flags:**

| Flag | |
|---|---|
| `--cloud hetzner`, `--region fsn1`, `--size small` | Where and how big. The region decides the cloud. |
| `--engine` | `postgresql` (default), `mysql`, `mariadb`, `valkey`, `clickhouse`, `opensearch`, `qdrant` or `meilisearch`. `rowsafe cloud sizes` lists what's offered. |
| `--engine-version V` | PostgreSQL 15 to 18 (default 17), MySQL 8.4, MariaDB 11.8, Valkey 8, ClickHouse 26.3 or 26.8 (default 26.8), OpenSearch 3, Qdrant 1.19, Meilisearch 1.54. |
| `--postgres 15\|16\|17\|18` | Same as `--engine postgresql --engine-version`. |
| `--allow me\|IP\|CIDR` | Repeatable. `none`: nobody connects until `rowsafe cloud allow`. |
| `--standby` | PostgreSQL only: a second server ready to take over. Doubles the price. |
| `--extensions vector,postgis,timescaledb` | PostgreSQL 15 to 18: pgvector, PostGIS, TimescaleDB (Apache-2.0 edition), on in the `postgres` database and every new one ([Extensions](/docs/guides/rowsafe-cloud#extensions)). |
| `--wait`, `--yes`, `--json` | `clone` takes these and `--allow` too. |

```sh
rowsafe cloud sizes
rowsafe cloud create shop-db --wait          # the cheapest size free now; only this computer may connect
rowsafe cloud create shop-mysql --engine mysql   # MySQL 8.4 (Intel and AMD sizes only)
rowsafe cloud create events --engine clickhouse  # ClickHouse 26.8 (sizes with 4 GB of memory or more)
rowsafe cloud create vectors --engine qdrant      # Qdrant 1.19 (sizes with 2 GB of memory or more; snapshots every 15 minutes)
rowsafe cloud create search-db --extensions vector,postgis   # pgvector and PostGIS on from the start
rowsafe env --on shop-db                     # DATABASE_URL in .env
rowsafe connect shop-db                      # psql, as a temporary user
rowsafe cloud allow shop-db 203.0.113.4      # let the app's server connect
rowsafe cloud resize shop-db medium
rowsafe cloud clone shop-db shop-test --at "10m ago" --delete-after 1d
rowsafe cloud passphrase shop-db --file shop-db-passphrase.txt
rowsafe cloud delete shop-db
```

## Backups, Proof and Marks

| Command | What it does |
|---|---|
| `rowsafe backup [NAME]` | Back up now. `--type full` (default), `diff` or `incr`. |
| `rowsafe backups [NAME]` | Backups, newest first. |
| `rowsafe proof [NAME]` | Run [Proof](/docs/concepts/restore-drills), the restore test, now. |
| `rowsafe proofs [NAME]` | Every Proof run and its result. |
| `rowsafe mark [NAME] [LABEL]` | Set a [Mark](/docs/concepts/restore-points) (a named restore point). `LABEL` defaults to `manual-<UTC time>`. `--json` prints the Mark (`status`, `restore_from_backup`, ...) for scripts and CI. |
| `rowsafe marks [NAME]` | Marks, with the backup to restore from. |
| `rowsafe rewind find [NAME]` | [Find the moment](/docs/guides/find-the-moment) rows were deleted or changed, or a table emptied or dropped. `--table T`, `--since 24h` or `--from`/`--to`, `--kind`, `--json`. Read-only. |
| `rowsafe tasks [NAME]` | Recent tasks. `--status S`, `--type T`, `--limit N` (default 30). |
| `rowsafe task ID` | One task with its full log. |

- Commands that run something wait for it, and exit `1` if it fails. `--no-wait` on `backup`, `proof` and `mark` returns at once.
- `rowsafe mark X` with one argument: `X` is the database if one has that name, else the label. So with `.rowsafe.json` naming `app`, `rowsafe mark before-drop` marks `app` as `before-drop`.

## Files

Folders that go with a database, like uploads ([guide](/docs/guides/files)).

| Command | What it does |
|---|---|
| `rowsafe files [NAME]` | Protected folders, status and last snapshot. `--json`. |
| `rowsafe files add [NAME] PATH` | Back up the folder `PATH` on the database server with the database. `--exclude cache,*.tmp` leaves files out. |
| `rowsafe files remove [NAME] PATH` | Stop backing it up (its snapshots age out). `--yes` skips the question. |
| `rowsafe files backup [NAME]` | Snapshot the folders now. `--no-wait` returns at once. |
| `rowsafe files restore [NAME] (--at TIME \| --mark LABEL)` | Bring files back; by default only missing ones. `--path REL` (repeatable) for listed paths, `--column DB:schema.table.column` for files a column points to, `--whole-folder` (kept for undo), `--overwrite` to also replace changed files, `--folder PATH` for one folder, `--preview` to only count. You type the database name unless `--yes`. |
| `rowsafe files undo [NAME]` | Undo the last whole-folder restore. |
| `rowsafe files proof [NAME]` | Restore a few files and compare them with the live ones, now. |

## Rewind

Same as the dashboard's **Rewind** page ([guide](/docs/guides/restore)). Owners and admins only, never a read-only key. Commands wait and print the result, e.g. `Brought back 1,204 rows in public.orders and 3,310 in public.order_items.`

| Command | What it does |
|---|---|
| `rowsafe rewind [NAME]` | Recovery window, newest Marks, the copy, data kept aside by a rewind, and the next command to run. `--json`. |
| `rowsafe rewind copy [NAME] (--at TIME \| --mark LABEL)` | Restore a copy next to production (never touches production). `--hours N` keeps it N hours (default 24, 1 to 168). `--no-wait` returns at once. |
| `rowsafe rewind compare [NAME] [TABLE...]` | Count, by primary key, rows missing in production, changed, and added since. No `TABLE`: every table. `--db DB`, `--json`. |
| `rowsafe rewind rows [NAME] TABLE...` | Bring back rows missing in production from the copy, after a Mark. `--include-changed` also resets changed rows to the copy's values. `--db DB`. You type the database name; `--yes` skips. |
| `rowsafe rewind extend [NAME]` | Keep the copy longer: `--hours N` from now (default 24, at most 168). |
| `rowsafe rewind drop [NAME]` | Delete the copy. Asks first; `--yes` skips. |
| `rowsafe rewind database [NAME] (--at TIME \| --mark LABEL)` | Rewind the whole live database. PostgreSQL stops during the restore; current data is kept aside 7 days. Only on servers that allow it. You type the database name; `--yes` skips. |
| `rowsafe rewind undo [NAME]` | Undo the latest rewind (put the data from before it back). You type the database name; `--yes` skips. |
| `rowsafe rewind cleanup [NAME]` | Delete data kept aside by a rewind, to free disk. The rewind can't be undone after. Asks first; `--yes` skips. |

- `TIME`, in your time zone: `"2026-09-24 14:04"`, `"2026-09-24 14:04:05"`, `"14:04"` (today), `"10m ago"`, `"2h ago"`, `"1h30m ago"`, or RFC 3339 (`2026-09-24T12:04:00Z`). Not in the future.
- `TABLE`: `schema.table`, or `table` for `public.table`. If the copy has several PostgreSQL databases: `DB:schema.table` or `--db DB`.

```sh
rowsafe rewind copy app --at "14:04"
rowsafe rewind compare app
rowsafe rewind rows app public.orders public.order_items
```

## Move in

Move a database from a managed provider onto a server Rowsafe protects ([guide](/docs/guides/move-in)). The source connection string is typed hidden, piped on stdin, or read from an environment variable, and encrypted on your machine to the server's key. Rowsafe never sees it.

| Command | What it does |
|---|---|
| `rowsafe migrate [NAME]` | Moves into `NAME` (or all) and their progress. `--json`. |
| `rowsafe migrate start [NAME]` | Check the source, start copying into `NAME`'s server, wait until caught up. `--into DB` (new database's name; default: the source's), `--method live` or `dump` (default: what the check recommends), `--source-env VAR` (connection string from `$VAR`), `--id ID` (check an existing move again), `--host ADDR` and `--user NAME` (with `dump`: the new connection string), `--yes`. Exits `1` when the check found something to fix. |
| `rowsafe migrate status ID` | Progress, the check's findings, the result. |
| `rowsafe migrate fix ID` | Set source tables without a primary key to `REPLICA IDENTITY FULL`, then check again. |
| `rowsafe migrate switch ID` | Switch over: the old database goes read-only (unless `--writes-stopped`), last changes arrive, sequences are set, row counts compared, and the new connection string is printed once. `--user NAME`, `--host ADDR`. |
| `rowsafe migrate password ID` | A new password for the apps' login, printed once. |
| `rowsafe migrate writable ID` | Make the old database writable again (rollback). |
| `rowsafe migrate cancel ID` | Stop, and remove Rowsafe's publication and replication slot from the old database. `--drop-copy` also deletes the partial copy. |
| `rowsafe migrate finish ID` | Forget the old database's connection string. |

## Standby

A [standby](/docs/guides/standby) is a readable second server, kept in sync, that takes over if the primary dies.

| Command | What it does |
|---|---|
| `rowsafe standby [NAME]` | The standby, its lag, fenced old primaries, automatic failover, and connection strings that follow the primary. `--json`. |
| `rowsafe standby add [NAME] --host SERVER` | Restore the latest backup on an empty cluster of `SERVER` and follow the primary. `--port N` (which cluster, if several), `--fingerprint F` (confirm the server's key without asking), `--no-stream` (follow through the bucket only), `--no-wait`. |
| `rowsafe standby promote [NAME]` | Make the standby the primary. The old primary is stopped for good first. `--primary-down` confirms it's down when its agent isn't reporting. `--force` promotes even if the standby misses some of its last changes. You type the name unless `--yes`. |
| `rowsafe standby rebuild [NAME] [--host SERVER]` | Turn the fenced old primary into the new standby. |
| `rowsafe standby unfence [NAME]` | Start the fenced primary again when the standby wasn't promoted. |
| `rowsafe standby failover [NAME] --on\|--off` | Automatic failover. `--after 3m`: how long every condition must hold. `--max-data-loss 1m`: the most changes it may lose. |
| `rowsafe standby remove [NAME]` | Remove the standby; its cluster gets its own data back. |

To compare fingerprints before pairing, run `sudo -u postgres rowsafe-agent key` on the server.

### Move to a new server

[Moving a database](/docs/guides/move) is a standby on the new server, then a planned switchover.

| Command | What it does |
|---|---|
| `rowsafe move [NAME] --to SERVER` | Set up the new server and keep it in sync. `--at TIME` switches over then by itself; without it, it waits for `move switch`. `--keep-days N` keeps the old server (stopped) as a way back, 1 to 30, default 7. `--port N`, `--fingerprint F`, `--no-wait` as for `standby add`. Without `--to`: the move in progress. |
| `rowsafe move switch [NAME]` | Switch over now. You type the name unless `--yes`. |
| `rowsafe move schedule [NAME] --at TIME` | Change when it switches over; `--clear` waits for `move switch`. |
| `rowsafe move cancel [NAME]` | Cancel before the switchover; the database stays put. |
| `rowsafe move back [NAME]` | Move back to the old server (its data is reused). |
| `rowsafe move finish [NAME]` | Remove the old server: Rowsafe stops keeping it stopped. |

## Fork

A [fork](/docs/guides/fork) is a new, independent database cloned from another (now, any second of its recovery window, or a Mark), with its own backups.

| Command | What it does |
|---|---|
| `rowsafe fork [SOURCE] --to SERVER` | Restore `SOURCE` on `SERVER` as a new database and wait for its first backup. `--to` can be the source's own server (a new port). Without `--at` or `--mark`, it forks now, after a Mark named `fork-<id>`. |
| `rowsafe forks [SOURCE]` | Forks of `SOURCE`, their status, and what `SOURCE` was forked from. `--json` adds each fork's masked columns. |

**`fork` flags:**

| Flag | |
|---|---|
| `--to SERVER` | Hostname or ID. Without it, lists the servers and why any can't take the fork. |
| `--name NAME` | The fork's name. Default `SOURCE-fork`. |
| `--at TIME` | A moment in the recovery window: `"2026-09-24 14:04"` (your time zone), `"14:04"`, `"10m ago"` or RFC 3339. |
| `--mark MARK` | A Mark instead of a time. |
| `--mask` | Mask personal data before anyone can connect. |
| `--port N` | The new cluster's port, 5440-5499. Default: a free one. |
| `--into-port N` | Use this existing, empty cluster instead. |
| `--fingerprint F` | Confirm another server's key fingerprint without asking (needed without a terminal). |
| `--no-wait` | Return once queued. |
| `--json` | Print the fork as JSON. |

## Database settings

```sh
rowsafe set [NAME] [--retention-full N] [--full-schedule CRON] [--diff-schedule CRON] [--proof-schedule CRON]
```

Only the flags you pass change. Schedules: 5-field cron in UTC, at most hourly. `--proof-schedule` sets when Proof runs. `--diff-schedule ""` turns differential backups off.

```sh
rowsafe set app --retention-full 4 --proof-schedule "0 4 * * 3"
```

| Command | What it does |
|---|---|
| `rowsafe remove NAME` | Stop managing a database. Never changes the server or the bucket. After a plan was applied, needs `--keep-archiving` (the server keeps archiving). `--yes` skips the confirmation. |

## Updates and upgrades

Only on servers where the installer allowed updates. Through MCP, only for [an agent acting as an owner or admin](/docs/guides/agent-autonomy). Security updates and reboots are fixes: `rowsafe fix NAME`. Guide: [Update and upgrade PostgreSQL](/docs/guides/updates).

| Command | What it does |
|---|---|
| `rowsafe update [NAME]` | Show versions, then install PostgreSQL's newest minor release (e.g. 16.9 to 16.10) and restart, after a Mark. You type the database name; `--yes` skips, `--no-wait` returns once queued. |
| `rowsafe update [NAME] --auto on\|off` | Install minor releases by itself on Sundays at 03:00 in `--timezone ZONE` (IANA, e.g. `Europe/Berlin`; default: your computer's). |
| `rowsafe upgrade [NAME]` | Versions, newer majors, the latest rehearsal, and an upgrade that can be undone. `--json`. |
| `rowsafe upgrade [NAME] --to 18` | Check, rehearse on a restored copy (unless a rehearsal to 18 passed in the last 14 days), then upgrade. `--mode safe` (default) or `fast`, `--rehearse-only`, `--yes` to skip typing the name. |
| `rowsafe upgrade undo [NAME]` | Go back to the version the upgrade kept (for 7 days). |
| `rowsafe upgrade cleanup [NAME]` | Remove the kept version to free disk; the upgrade can't be undone after. |

## Pulse: monitoring and alerts

| Command | What it does |
|---|---|
| `rowsafe alerts` | Firing alerts. `--all` adds resolved ones; `--resolved` shows only those. |
| `rowsafe alerts ack ID` | Acknowledge a firing alert: no more reminders. |
| `rowsafe alerts rules` | Built-in alert rules with your organization's settings. |
| `rowsafe pulse [NAME]` | [Pulse](/docs/guides/monitoring): health score (0-100) and findings with what to do. Without NAME: every database, worst first. Exits `3` if one scores below 70. `--json`. |
| `rowsafe fix [NAME] [FINDING [FIX] \| NUMBER]` | Numbered fixes for what `pulse` found (clean up tables, refresh statistics, add, rebuild or remove an index, end a stuck session, remove an inactive slot, back up now...). In a terminal, asks which to apply. `rowsafe fix app 2` applies number 2; `rowsafe fix app FINDING FIX` names it by ID. Asks before running; fixes that end a session or remove something ask you to type the database name. `--yes` skips. Same as [Apply fix](/docs/guides/monitoring#apply-fix) in the dashboard. |
| `rowsafe insights [NAME]` | Largest tables and indexes, unused and duplicate indexes, estimated bloat, dead rows and vacuum, transaction ID age. `--limit N`, `--json`. |
| `rowsafe top [NAME]` | Queries that took the most time, and which got slower. `--since 24h` (e.g. `1h`, `168h`), `--sort total_time\|calls\|mean_time\|rows`, `--query ID` (one query over time), `--json`. Needs `pg_stat_statements`. |
| `rowsafe recommendations [NAME]` | [Recommendations](/docs/guides/recommendations) (schema, queries, capacity, indexes): why, and what each costs. Without NAME: each database's top one. `--group schema\|queries\|capacity\|indexes`, `--dismissed`, `--json`. `--dismiss ID [--reason not_relevant\|intended\|later\|wrong] [--note TEXT]` sets one aside; `--restore ID` brings it back. Apply the ones Rowsafe can do with `rowsafe fix`. |
| `rowsafe recommendations find [NAME]` | Test index ideas on a copy now (it also runs nightly) and wait; proven indexes appear in the Indexes group. `--no-wait`. |
| `rowsafe recommendations schedule [NAME] auto\|off\|CRON` | When to test index ideas: `auto` (nightly at the quietest hour), `off`, or 5-field cron in UTC. |
| `rowsafe report` | The "Your weekly Pulse" email: show settings, `--preview` (`--html`), `--on`/`--off`, `--to A,B`, `--send-test`. |
| `rowsafe activity NAME` | Queries running, or idle in a transaction, for over a minute. |
| `rowsafe channels list` | Notification channels. |
| `rowsafe channels add --type email --name NAME --address A [--address B]` | Email channel. |
| `rowsafe channels add --type slack\|discord\|webhook --name NAME --url URL` | Slack, Discord or webhook channel. A webhook prints its signing secret once. |
| `rowsafe channels remove ID` | Remove a channel. |
| `rowsafe channels test ID` | Send a test notification now. |

## Connection pooling

[Connection pooling](/docs/guides/connection-pooling) with PgBouncer. Only where the installer allowed it (`--allow-pooler`), and not in Docker. Read-only keys can't change it. AI agents (MCP) change it [as their person](/docs/guides/agent-autonomy), if that person is an owner or admin.

| Command | What it does |
|---|---|
| `rowsafe pooling status [NAME]` | State, settings, direct and pooled connection strings, busiest pools. `--json`. |
| `rowsafe pooling on [NAME]` | Install PgBouncer if needed and start it. If already on, changes the settings you pass and keeps the rest. Asks first; `--yes` skips. |
| `rowsafe pooling off [NAME]` | Stop PgBouncer and remove what Rowsafe installed. Apps using it must connect directly again. Asks first; `--yes` skips. |

**`pooling on` flags** (left out: Rowsafe picks, or keeps the current value):

| Flag | Default | |
|---|---|---|
| `--mode transaction\|session` | `transaction` | How PgBouncer shares connections ([which one](/docs/guides/connection-pooling#transaction-or-session-mode)). |
| `--pool-size N` | From `max_connections` and CPUs | PostgreSQL connections per database and user. |
| `--max-client-conn N` | `1000` | Client connections PgBouncer accepts. |
| `--listen local\|private\|public` | `local` | This server only; also its private network; or every address (only where root allowed `--allow-pooler-public`). |
| `--port N` | `6432` | PgBouncer's port. |

## Settings and tuning

Nothing restarts: settings that need a restart wait for `rowsafe restart` (or the next restart).

| Command | What it does |
|---|---|
| `rowsafe settings [NAME] [SETTING]` | PostgreSQL's settings that matter, by group: value, default, where it's set, whether a change needs a restart, and how many changes Rowsafe recommends. With SETTING: that one, explained. `--all` adds other settings from config files; `--json`. |
| `rowsafe tune [NAME]` | Changes that suit this server's memory, CPUs and disk, each with why; applies them after asking. `--workload web\|analytics\|mixed`, `--disk ssd\|hdd` (remembered), `--all` adds optional changes, `--json` prints and changes nothing. [Tuning](/docs/guides/tuning). |
| `rowsafe settings set [NAME] SETTING=VALUE...` | A Mark, then `ALTER SYSTEM` and a reload. `VALUE` `default` resets one. Refused: Rowsafe's archiving settings and values PostgreSQL might not start with. `--yes`, `--no-wait`. |
| `rowsafe settings undo [NAME] [CHANGE_ID]` | Undo the latest change made through Rowsafe (or CHANGE_ID). `--yes`. |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success. `status`: protected, or all healthy. `guard --check`: destructive. |
| `1` | An error, a failed task, a cancelled confirmation. `guard --check`: not destructive. |
| `2` | `rowsafe` without arguments. `guard`: blocked because protection is required. `preview --fail-on`: the migration fails on the copy. |
| `3` | `status`: not protected, or the fleet has warnings or critical problems. `pulse`: a database scores below 70. `preview --fail-on`: the verdict is at or above it. |

## `.rowsafe.json`

Names the project's database for the CLI, the MCP server and the guard hook:

```json title=".rowsafe.json"
{
  "database": "app",
  "require_protection": false
}
```

| Field | |
|---|---|
| `database` | The database's name in Rowsafe. |
| `require_protection` | For `guard` only: block destructive commands when the database isn't protected. |

`rowsafe init app` writes it here, keeping other fields. Commands look in this directory, then each parent. It holds no secrets: commit it.
