Rowsafe protects the databases you already run, on your own servers or in Docker. It takes backups, keeps a continuous record of every change, and restores your latest backup every week to prove it works. If something goes wrong, you can get your data back to the second before it happened.

You keep your database where it is. You don't move it to a hosted service.

## How it works

```text
You: dashboard, CLI, AI agents
        │
        │ HTTPS
        ▼
┌─────────────────────────┐
│ Rowsafe service         │
│ schedules, history,     │
│ alerts                  │
└─────────────────────────┘
        ▲
        │ HTTPS, outbound only
        │ (the agent asks for work)
┌─────────────────────────┐
│ Your server             │
│ agent ──▶ your database │
└─────────────────────────┘
        │
        │ encrypted backups
        ▼
Your S3-compatible bucket
```

1. A small open-source **agent** runs next to your database. It only makes outbound HTTPS requests. Nothing on your server listens for Rowsafe.
2. The agent encrypts backups **on your server** and sends them to **your own bucket**. (Or to [Rowsafe Storage](/docs/guides/rowsafe-storage), a bucket run by Rowsafe, if you'd rather not set one up.) Rowsafe never sees your data, your bucket keys or your encryption passphrase.
3. The hosted **Rowsafe service** schedules backups and the weekly Proof, keeps the history, watches for problems and alerts you.

Read [How Rowsafe works](/docs/concepts/how-it-works) for the details.

## Supported databases

| Database | Status | Where |
|---|---|---|
| PostgreSQL 13 to 18 | **Supported** | Linux servers (Debian 12/13, Ubuntu 22.04/24.04) and Docker (official `postgres` images, 14 to 18) |
| MySQL 8.0, 8.4 | **Supported** | Debian 12/13, Ubuntu 22.04/24.04, and Docker. See [MySQL and MariaDB](/docs/guides/mysql) |
| MariaDB 10.6, 10.11, 11.4 | **Supported** | Debian 12/13, Ubuntu 22.04/24.04, and Docker. See [MySQL and MariaDB](/docs/guides/mysql) |
| MongoDB 6.0, 7.0, 8.0 | **Supported** | Replica sets (one member is enough) on Debian 12/13, Ubuntu 22.04/24.04, and Docker (official `mongo` images); not sharded clusters. See [Protect MongoDB](/docs/guides/mongodb) |
| ClickHouse 24.8 and newer | **Supported** | Single servers on Debian 12/13, Ubuntu 22.04/24.04, and Docker (official `clickhouse/clickhouse-server` images, 25.8 to 26.8). See [Protect ClickHouse](/docs/guides/clickhouse) |
| Redis 7.0 and newer, Valkey 7.2 and newer | **Supported** | Standalone servers (with or without replicas) on Debian 12/13, Ubuntu 24.04, Redis's own packages, and Docker (official `redis` 7.2 to 8.10 and `valkey/valkey` 7.2 to 9.2 images); not Redis Cluster or Sentinel. Every feature except connection pooling and migration previews. See [Protect Redis or Valkey](/docs/guides/redis) |
| SQLite 3 | **Supported** | Database files your apps open, on local disk: Debian 12/13, Ubuntu 22.04/24.04, and Docker (the agent as a sidecar). Every feature that doesn't need a database server; restore to any second needs WAL mode. See [Protect SQLite](/docs/guides/sqlite) |

Every Rowsafe feature works for PostgreSQL, MySQL, MariaDB, MongoDB and ClickHouse, with a few exceptions: MongoDB needs no connection pooling (its drivers pool connections themselves). Redis and Valkey get everything except connection pooling (Redis doesn't need it) and migration previews (Redis has no schema): [what's not there](/docs/guides/redis#not-yet). The examples on most pages use PostgreSQL; each guide says what differs per database, and each database's guide lists its limits: [MySQL and MariaDB](/docs/guides/mysql#limits), [MongoDB](/docs/guides/mongodb#limits), [ClickHouse](/docs/guides/clickhouse#limits), [Redis and Valkey](/docs/guides/redis#limits).

SQLite runs inside your app, with no database server, so it has backups, restore to any second, Marks, Proof, Rewind, Pulse with one-click fixes, files, a second copy, Find the moment, safe copies, migration previews, security checks, recommendations, index advice and clones, but no restart, standby, pooling, server updates, Databases & users, logs or tuning (there is no server). Moving in from Turso or Cloudflare D1 isn't available yet: see [its limits](/docs/guides/sqlite#limits).

## Safety first

Rowsafe works on production databases, so it is careful by design:

- **It never restarts your database on its own.** When a setting needs a restart, Rowsafe asks first. Say no, and you restart when it suits you.
- **Nothing changes until you say yes.** Rowsafe first shows, in plain words, what it will change.
- **Proof is isolated.** The weekly restore test restores into a scratch directory on a private socket, then deletes it. It can't touch production or its backups.
- **Your secrets stay on your server.** Backups are encrypted before they leave it.
- **Signed releases.** The agent only installs and runs releases signed by Rowsafe, and rolls back a bad update by itself.

## Every feature

One line each, grouped by what you want to do. The [features page](/features) lists them too.

### Rewind: get data back

- [Restore a database](/docs/guides/restore): go back to any second or to a Mark. Restore a copy and bring back rows, or rewind the whole database, with undo.
- [Find the moment](/docs/guides/find-the-moment): find the exact second rows were deleted or a table was dropped.

- [Backups and point-in-time recovery](/docs/concepts/backups-and-recovery): full and differential backups plus every change, and how far back you can go.

### Proof: know your backups restore

- [Proof](/docs/concepts/restore-drills): every week, Rowsafe restores your latest backup on a scratch copy and checks it.
- [Protection status](/docs/concepts/protection-status): one yes-or-no answer to "could this database be restored right now?".

- [Monitoring and alerts](/docs/guides/monitoring): the health score, findings with **Apply fix**, alerts, slow queries and the Monday email.
- [Logs](/docs/guides/logs): your database's own log in the dashboard, with values removed on your server.

- [Recommendations](/docs/guides/recommendations): what will bite later, and indexes proven on a copy of your database.
- [Ask Rowsafe](/docs/guides/ask): ask about your databases in plain words.
