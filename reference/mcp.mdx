Rowsafe's [MCP](https://modelcontextprotocol.io) server lets AI assistants read what the dashboard shows and, if you allow it, set Marks, run backups, Proof and checks, change production, or create [Rowsafe Cloud](/docs/guides/rowsafe-cloud) servers. Changes run right away **as the person who connected the agent**, with that person's dashboard rights, or Rowsafe refuses them and says why ([How AI agents act](/docs/guides/agent-autonomy)). Part of [Guard](/docs/guides/ai-agents).

| | Transport | Credentials | Write tools |
|---|---|---|---|
| `rowsafe mcp` | stdio, on your machine | The CLI's login, or `ROWSAFE_API_KEY` | Off by default. `--allow-restore-points` or `--allow-writes`. |
| `https://api.rowsafe.sh/mcp` | Streamable HTTP | **Sign in with Rowsafe** (OAuth), or `Authorization: Bearer rsk_...` | API keys: always listed (a read-only key can't use them). Signed-in apps: `create_restore_point` with **Save Marks**; write tools, `request_change`, the change tools and `create_app_database` with **Act for you**. |

ChatGPT, Claude, Cursor, VS Code, Codex or Windsurf: see [Connect AI apps](/docs/guides/connect-ai-apps).

## Set up

<Tabs items={["Claude Code", "Claude Desktop", "Remote endpoint"]}>
<Tab value="Claude Code">

Run `rowsafe login` first, then pick a mode:

```sh
# Read-only
claude mcp add rowsafe -- rowsafe mcp

# Read-only, plus Marks (what the Claude Code plugin uses)
claude mcp add rowsafe -- rowsafe mcp --allow-restore-points

# Also backups, Proof, checks, schedules, and changes to production as you
claude mcp add rowsafe -- rowsafe mcp --allow-writes

# A specific key instead of your login, in every project
claude mcp add --scope user rowsafe -e ROWSAFE_API_KEY=rsk_... -- rowsafe mcp
```

`--scope project` writes `.mcp.json` into your repo for everyone. Don't put a key there; use the stdio form (each developer's own login).

</Tab>
<Tab value="Claude Desktop">

Edit the config (**Settings**, **Developer**, **Edit Config**): `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS, `%APPDATA%\Claude\claude_desktop_config.json` on Windows.

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "rowsafe": {
      "command": "/usr/local/bin/rowsafe",
      "args": ["mcp"],
      "env": {
        "ROWSAFE_API_KEY": "rsk_..."
      }
    }
  }
}
```

- Use the absolute path (`which rowsafe`): Desktop ignores your shell's `PATH`.
- Add `"--allow-restore-points"` or `"--allow-writes"` to `args` for write tools.
- Restart Claude Desktop.

Or, with no key or local binary: **Settings**, **Connectors**, **Add custom connector**, `https://api.rowsafe.sh/mcp`, and sign in with Rowsafe ([Connect AI apps](/docs/guides/connect-ai-apps)).

</Tab>
<Tab value="Remote endpoint">

No local binary. Sign in with Rowsafe:

```sh
claude mcp add --transport http rowsafe https://api.rowsafe.sh/mcp
```

Then run `/mcp` in Claude Code and choose **Authenticate**. Or use an API key (CI):

```sh
claude mcp add --transport http rowsafe https://api.rowsafe.sh/mcp --header "Authorization: Bearer rsk_..."
```

- Every request needs an OAuth token or an API key. For an assistant that must never change anything, use a [read-only key](/docs/guides/teams#api-keys) (`rowsafe api-keys create NAME --read-only`).
- Stateless; answers with plain JSON.
- Tool calls wait at most 45 seconds.

</Tab>
</Tabs>

## Sign in with Rowsafe (OAuth)

The remote endpoint is an OAuth 2.1 protected resource per the [MCP authorization spec](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) (2026-07-28). Clients discover everything from the first `401`: give them only the URL.

| | |
|---|---|
| Protected resource metadata ([RFC 9728](https://www.rfc-editor.org/rfc/rfc9728)) | `https://api.rowsafe.sh/.well-known/oauth-protected-resource/mcp`, named in `WWW-Authenticate` on every `401` |
| Authorization server metadata ([RFC 8414](https://www.rfc-editor.org/rfc/rfc8414)) | `https://api.rowsafe.sh/.well-known/oauth-authorization-server` (issuer `https://api.rowsafe.sh`) |
| Client registration | Client ID metadata documents (an HTTPS `client_id`), or dynamic registration ([RFC 7591](https://www.rfc-editor.org/rfc/rfc7591)) at `/oauth/register`. Public clients, no secret. |
| Grant | Authorization code with PKCE, `S256` only. The response carries `iss` ([RFC 9207](https://www.rfc-editor.org/rfc/rfc9207)). |
| Redirect URIs | Exact match. ChatGPT's, Claude's, VS Code's and Cursor's published callbacks, and loopback (`http://127.0.0.1`, `http://[::1]`, `http://localhost`, any port). |
| Resource ([RFC 8707](https://www.rfc-editor.org/rfc/rfc8707)) | `https://api.rowsafe.sh/mcp`. Tokens work on `/mcp` only. |
| Scopes | `rowsafe:read` (always). `rowsafe:marks` (optional, **Save Marks**: adds `create_restore_point`). `rowsafe:act` (optional, **Act for you**: adds the write tools, copy tools, `request_change`, `create_cloud_server`, `cloud_firewall`, `apply_fix`, `create_app_database`, and lets the app act as the person who allowed it). `offline_access` accepted; other scopes ignored. |
| Tokens | Access: 1 hour. Refresh: 30 days, single use, rotated each refresh; reusing one disconnects the app. Revocation ([RFC 7009](https://www.rfc-editor.org/rfc/rfc7009)) at `/oauth/revoke`. |

An owner or admin approves each app in the dashboard, for one organization; the app then acts as that person. **Settings**, **Connected apps** lists apps, who allowed them, whether they can act yet, and lets you disconnect them.

## Safety model

- **Same API as the CLI.** Same key, checks, plan limits and audit log. Every change is in `rowsafe audit`, attributed to the key or app and the person it acts as.
- **Only what the API can do.** Tools queue fixed agent tasks and change schedules. Nothing runs commands or SQL on production or reads backup contents: Rowsafe can't.
- **Changes to production run as the agent's person.** Restores, rewinds, restarts, fixes, settings, updates, standbys, moves, pooling, security fixes, Rowsafe Cloud servers and the rest go through `request_change` (or `create_cloud_server`, `cloud_firewall`, `apply_fix`, `create_app_database`). Rowsafe checks the current role of the person behind the agent (who allowed the app, made the key, or approved the CLI login). Owner or admin: it makes the dashboard's own API call as them, at once, with the same checks, confirmations and Marks. Restarts still need root's permission at install. The tools never call those endpoints directly.
- **Or Rowsafe refuses, and nothing changes.** For example: a member's agent, a key made by another key, an app or key from before agents could act, no backup before a destructive change, a first payment only an owner can make, a server key to compare, over the agents' budget. The agent tells you the reason. Nothing waits for a person. Keys and assistants can't change what AI agents may do. [When Rowsafe refuses](/docs/guides/agent-autonomy#when-rowsafe-refuses).
- **Read-only unless you say otherwise.** `rowsafe mcp` registers read tools plus copy tools, which never touch production (`preview_migration` runs SQL on a fresh copy as a regular role; `create_safe_copy` makes masked copies only, within your plan). `--allow-restore-points` adds only `create_restore_point`. `--allow-writes` adds actions that don't touch production, `request_change`, `create_cloud_server`, `cloud_firewall`, `apply_fix` and `create_app_database`.
- **No secrets through Rowsafe.** People set passwords in the dashboard: new users, resets, restored copies, safe copies made through the remote endpoint. Exception, `create_app_database`: from local `rowsafe mcp` the password is made on your machine and only its verifier is sent; on the remote endpoint the person creates the database in the dashboard, where only their browser sees the password. Bucket keys and the passphrase never leave your server. Outputs are size-capped.
- **Not exposed:** enrollment tokens, API keys, removing hosts, members and roles, plan changes, agent update settings, what root allowed on a server.
- **Annotations.** Read tools are marked read-only. `request_change`, `cloud_firewall`, `apply_fix`, `update_schedule` (lower retention deletes old backups) and `delete_safe_copy` are marked destructive, so clients that confirm destructive calls ask you. Tool descriptions also tell agents to confirm disruptive, destructive or paid changes with you in chat first.

## Tools

**Read**: always there. **Marks**: `--allow-restore-points` or **Save Marks**. **Copies** (never production): always for `rowsafe mcp` and API keys; signed-in apps need **Act for you**. **Write**: `--allow-writes`, a read-write key, or **Act for you**.

### Changes to production

| Tool | Access | What it does |
|---|---|---|
| `request_change` | write | Change production: `action`, `database`, `params` and your `reason`, like the dashboard's button. Runs at once: the answer starts with *Done*, names the person it ran as, and the change is `approved` (done) or `failed`, with its result and dashboard page. Or: *Rowsafe refused this change, and nothing changed:* and the reason. |
| `create_cloud_server` | write | Create a Rowsafe Cloud server: `name`, `region`, `size`, `engine` (PostgreSQL unless `mysql`, `mariadb`, `valkey`, `clickhouse`, `opensearch`, `qdrant` or `meilisearch`), `engine_version`, `allowed_ips`, `standby`, `extensions`, `reason`. Same as `request_change` `create_cloud_server`. When a first payment is needed, an owner's agent gets a `checkout_url` for you; the server is created once paid. |
| `cloud_firewall` | write | Set who can connect to a Rowsafe Cloud server: `server` and the whole new `allowed_ips` list. Same as `request_change` `cloud_firewall`. |
| `apply_fix` | write | Apply a fix Rowsafe proposed: `database`, `finding_id`, `fix_id`, and `confirm` if it restarts the database. Like **Apply fix**: Rowsafe recomputes the fix and saves a Mark first when the fix says so. |
| `describe_change` | read | Actions by group, with risk and the JSON schema of their params. For one action, also whom it would run as here and what would make Rowsafe refuse it. |
| `get_approval` | read | One change an agent made: `approved` (done, with its tasks) or `failed` (with why). Older records may say `pending`, `denied`, `expired` or `cancelled`: those never ran. Name kept for compatibility. |
| `list_approvals` | read | Changes AI agents and API keys made, newest first. |
| `create_app_database` | write | A new empty database and its owner user, for the app you're building, on a Rowsafe Cloud server running PostgreSQL 15+, MySQL, MariaDB or ClickHouse. Rowsafe never sees the password. PostgreSQL from local `rowsafe mcp`: made on your machine, created at once as the agent's person (an owner or admin), full connection string returned. MySQL, MariaDB, ClickHouse, and the remote endpoint: the tool says so, and the person creates it in the dashboard (**Databases & users**), which shows the connection string once. Valkey has no separate databases: make the app's login in the dashboard. OpenSearch, Qdrant and Meilisearch: the person makes the app's user or API key in the dashboard (**Databases & users**), shown once. |

The actions `request_change` can make:

| Group | Actions |
|---|---|
| Pulse | `apply_fix`, `change_settings`, `revert_settings`, `index_check_settings`, `restart`, `turn_on_backups` |
| Rewind | `restore_copy`, `compare_copy`, `extend_copy`, `delete_copy`, `bring_back_rows`, `rewind_in_place`, `undo_rewind`, `finish_rewind` |
| Updates | `update_database`, `upgrade_database`, `undo_upgrade`, `finish_upgrade`, `security_updates`, `reboot_server`, `auto_updates` |
| Standby | `create_standby`, `promote_standby`, `rebuild_standby`, `remove_standby`, `unfence`, `forget_fence`, `failover_settings` |
| Move | `move_database`, `move_schedule`, `move_switch`, `move_cancel`, `move_switch_back`, `move_finish`, `fork_database`, `restore_elsewhere`, `retire_database` |
| Security | `pooling_on`, `pooling_off`, `security_settings`, `security_action` |
| Data | `create_app_database` (through the `create_app_database` tool), `manage_databases_users`, `masking_rules`, `delete_database` |
| Files | `restore_files`, `undo_files_restore`, `restore_server_files`, `undo_server_files_restore` |
| Alerts | `alert_rule` |
| Rowsafe Cloud | `create_cloud_server`, `cloud_firewall`, `resize_cloud_server`, `clone_to_new_server`, `delete_cloud_server` |

- **Paid.** `create_cloud_server`, `resize_cloud_server` and `clone_to_new_server` record the size and price; the agent tells you first. A first payment is always an owner's: an owner's agent gets the checkout link, others are refused. `delete_cloud_server` is destructive: Rowsafe types the server's name for the agent and records it. [Rowsafe Cloud changes](/docs/guides/agent-autonomy#rowsafe-cloud-changes).
- **Extensions.** `manage_databases_users` turning on `vector`, `postgis` or `timescaledb` installs the package first where root allowed PostgreSQL updates. `timescaledb` needs `restart: true` in `params` unless already loaded: Rowsafe saves a Mark, then restarts PostgreSQL once (apps disconnect for a few seconds); the agent tells you first. [Extensions](/docs/guides/databases-and-users#pgvector-postgis-and-timescaledb).
- **Restart later.** `restart` takes `params.at`: a time (RFC 3339, up to 30 days ahead) or `"window"` for a Rowsafe Cloud server's next maintenance window. [Restart now or later](/docs/guides/monitoring#restart-now-or-later).
- **A lost server.** `restore_elsewhere` restores a database whose server has been silent 10 minutes onto another server with the same storage and passphrase (`name`, `host_id`, and `at` or `mark`; neither: the latest point). `retire_database` then removes the old one (`confirm`: its name); its backups are kept. [Server lost](/docs/guides/restore#server-lost-restore-to-another-server).
- **A server's files.** `restore_server_files` and `undo_server_files_restore` take `host` (hostname or ID) and `confirm` (its hostname). [A server's own files](/docs/guides/files#a-servers-own-files).
- **Always refused.** `create_standby`, `rebuild_standby`, `move_database` and `fork_database`: a person compares the server's key in the dashboard or CLI. A destructive action with no backup yet (the agent can `run_backup` and retry). Where Proof runs is a dashboard setting agents can't change.
- **Within a budget.** `create_cloud_server` runs on the owner's behalf, plus `create_app_database`, `cloud_firewall` and `clone_to_new_server` on servers created this way; everything else runs as the agent's person. [When Rowsafe refuses](/docs/guides/agent-autonomy#when-rowsafe-refuses).

Two prompts: `incident_triage` checks the fleet, reads the evidence behind each problem, and proposes next steps without changing anything. `fix_what_pulse_found` lists a database's fixable findings, lets you pick, and files each with `request_change`.

## Troubleshooting

- **"not logged in"** in the client's MCP log: run `rowsafe login`, or set `ROWSAFE_API_KEY` in the server's environment.
- **Tools missing:** write tools, `request_change` and the change tools need `--allow-writes`; Marks need `--allow-restore-points`. Restart the client after changing flags. A signed-in app needs **Act for you** (and **Save Marks**); reconnect it to change that.
- **`forbidden (403): This API key is read-only.`:** the key can only read.
- **"Rowsafe refused this change, and nothing changed":** the reason follows ([When Rowsafe refuses](/docs/guides/agent-autonomy#when-rowsafe-refuses)). If the app or key predates agents acting as their person, that person clicks **Let it act as me** in **Settings → Connected apps** (or **Let agents using it act as me** under **API keys**), or reconnects it.
- **A new Rowsafe Cloud server isn't created yet:** it waits for its first payment. An owner pays at the checkout link the agent gave.
- **A 402 error:** a plan limit is reached. `get_org` shows usage.
- **Smoke test** without a client:

  ```sh
  printf '%s\n' \
    '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"0"}}}' \
    '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
    '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | (cat; sleep 2) | rowsafe mcp
  ```
