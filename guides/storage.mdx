---
title: Set up backup storage
description: Create a bucket and access key for your backups, on R2, B2, S3, Wasabi, Spaces or any S3-compatible storage.
---

<Callout title="Don't want to set up a bucket?">
  Use [Rowsafe Storage](/docs/guides/rowsafe-storage): nothing to set up, still encrypted on your server. Or follow this page: about 10 minutes, and Cloudflare R2's first 10 GB are free.
</Callout>

Your backups live in a bucket **you own**. Rowsafe never stores your data and never sees the bucket's keys: they stay on your server.

You need:

1. **The bucket URL** of an empty, private bucket just for Rowsafe.
2. **An access key** (ID and secret) that can read, write and delete in it.
3. **An encryption passphrase.** The installer makes one.

The installer asks for the **bucket URL first**, works out the provider, region and name from it, then asks for the key. It **tests the bucket** before it finishes. You never paste keys into the dashboard.

<Callout title="Which provider should I pick?">
  No preference? **Cloudflare R2**: the first 10 GB are free and downloads (restores) cost nothing. Every provider below works the same way.
</Callout>

## Cloudflare R2

<Steps>
<Step>

### Create a bucket

In the [Cloudflare dashboard](https://dash.cloudflare.com), open **R2 Object Storage**, then **Create bucket** (for example `mycompany-rowsafe`). For EU data, set the location to **European Union (EU jurisdiction)**. Leave public access off.

</Step>
<Step>

### Copy the bucket URL

In the bucket's **Settings**, copy the **S3 API** URL:

```text
https://<account-id>.r2.cloudflarestorage.com/mycompany-rowsafe
```

An EU bucket has `.eu` in it: `https://<account-id>.eu.r2.cloudflarestorage.com/mycompany-rowsafe`.

</Step>
<Step>

### Create an access key

In R2, **Manage API tokens**, then **Create API token**. Pick **Object Read & Write**, limited to your new bucket. Copy the **Access Key ID** and **Secret Access Key**: they're shown once.

</Step>
</Steps>

## Backblaze B2

<Steps>
<Step>

### Create a bucket

In your [Backblaze account](https://secure.backblaze.com/b2_buckets.htm), **Create a Bucket**. Make it **Private**.

</Step>
<Step>

### Copy the bucket URL

The bucket's **Endpoint** (like `s3.us-west-004.backblazeb2.com`), then the bucket name:

```text
https://s3.us-west-004.backblazeb2.com/mycompany-rowsafe
```

</Step>
<Step>

### Create an application key

**Application Keys**, then **Add a New Application Key**: **your new bucket only**, **Read and Write**. Copy the **keyID** (access key ID) and **applicationKey** (secret). It's shown once.

</Step>
</Steps>

## Amazon S3

<Steps>
<Step>

### Create a bucket

In the [S3 console](https://console.aws.amazon.com/s3/), **Create bucket** in a region near your server. Keep **Block all public access** on.

</Step>
<Step>

### Copy the bucket URL

Either form works:

```text
https://mycompany-rowsafe.s3.eu-central-1.amazonaws.com
https://s3.eu-central-1.amazonaws.com/mycompany-rowsafe
```

</Step>
<Step>

### Create an access key for Rowsafe only

In IAM, create a user for Rowsafe (no console access) with a policy for this bucket only:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow", "Action": "s3:ListBucket", "Resource": "arn:aws:s3:::YOUR-BUCKET" },
    { "Effect": "Allow", "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"], "Resource": "arn:aws:s3:::YOUR-BUCKET/*" }
  ]
}
```

Create an **access key** for that user and copy the ID and secret.

</Step>
</Steps>

## Wasabi

<Steps>
<Step>

### Create a bucket

In the [Wasabi console](https://console.wasabisys.com), **Create Bucket** in a region. Keep it private.

</Step>
<Step>

### Copy the bucket URL

The region's endpoint, then the bucket name:

```text
https://s3.eu-central-1.wasabisys.com/mycompany-rowsafe
```

</Step>
<Step>

### Create an access key

Create a sub-user with programmatic access and a policy for this bucket only (read, write, delete). Create an **access key** and copy the key and secret.

</Step>
</Steps>

## DigitalOcean Spaces

<Steps>
<Step>

### Create a Space

In the [DigitalOcean control panel](https://cloud.digitalocean.com/spaces), **Create a Spaces Bucket** in a region (like `fra1`). Keep file listing restricted.

</Step>
<Step>

### Copy the bucket URL

Copy the Space's **Origin Endpoint**:

```text
https://mycompany-rowsafe.fra1.digitaloceanspaces.com
```

</Step>
<Step>

### Create an access key

**Spaces Object Storage > Access Keys**: create a key with read, write and delete, limited to this bucket if you can. Copy the key and secret.

</Step>
</Steps>

## Other S3-compatible storage

Any S3 storage over HTTPS works: MinIO, Ceph, Hetzner, OVHcloud, Scaleway and others. Create a private bucket and a key limited to it.

The bucket URL is the endpoint, then the bucket name: `https://s3.example.com/mycompany-rowsafe` or `https://s3.example.com:9000/mycompany-rowsafe`.

## The encryption passphrase

Backups are encrypted **on your server** before upload, so your provider only sees scrambled data. The installer makes a strong passphrase and shows it **once**.

<Callout type="warn" title="Save the passphrase in your password manager">
  Without it, your backups can't be restored. Rowsafe has no copy. The installer asks for its last 4 characters to confirm you saved it.
</Callout>

## Without questions

For automation, set `ROWSAFE_REPO_S3_ENDPOINT`, `ROWSAFE_REPO_S3_BUCKET`, `ROWSAFE_REPO_S3_KEY`, `ROWSAFE_REPO_S3_KEY_SECRET` and `ROWSAFE_REPO_CIPHER_PASS` in the installer's environment. It then asks nothing about storage. Example: [Adopt an existing database](/docs/guides/adopt#automate-it). Every setting: [Agent configuration](/docs/reference/agent-configuration#bucket-repository).

## Good to know

- **Use a dedicated, empty, private bucket.** Rowsafe never needs public access.
- **No lifecycle or auto-delete rules.** Rowsafe removes old backups itself; a rule could delete files newer backups depend on.
- **Test the settings again** on the server:

  ```sh
  curl -fsSL https://rowsafe.sh | sudo sh -s -- --check-storage
  ```

- **Change storage later** with `--setup-storage`. Keep your existing passphrase when it offers: earlier backups need it.
