---
title: Quickstart
description: Protect your first PostgreSQL database in about 10 minutes.
---

Create a bucket, run one command on your server, answer a few questions. Nothing changes until you say yes. New words are in the [Glossary](/docs/glossary).

**You need:**

- A Linux server (Debian 12/13 or Ubuntu 22.04/24.04) running PostgreSQL 13 to 18, with `sudo`.
- A storage bucket: Cloudflare R2 (10 GB free), Backblaze B2, Amazon S3, Wasabi, DigitalOcean Spaces or any S3-compatible storage.
- A few seconds of downtime for one PostgreSQL restart, now or later.

Other setups use the same command: [Docker](/docs/guides/docker), [MySQL and MariaDB](/docs/guides/mysql), [MongoDB](/docs/guides/mongodb), [ClickHouse](/docs/guides/clickhouse), [Redis and Valkey](/docs/guides/redis), [OpenSearch](/docs/guides/opensearch), [Qdrant](/docs/guides/qdrant), [Meilisearch](/docs/guides/meilisearch).

<Callout title="Production database?">
  Follow [Adopt an existing database](/docs/guides/adopt) instead. It adds preflight checks and a rollback plan.
</Callout>

<Steps>
<Step>

### Create an account

[Sign up](https://app.rowsafe.sh/sign-up). The Free plan covers one server with up to three databases, every feature included.

</Step>
<Step>

### Create a bucket and an access key

Create a **private**, empty bucket (for example `app-rowsafe`) and an access key limited to **that bucket only**. Keep at hand:

- the **bucket URL**, for example `https://<account-id>.r2.cloudflarestorage.com/app-rowsafe`
- the **access key ID**
- the **secret**

Where to find them, per provider: [Set up backup storage](/docs/guides/storage).

</Step>
<Step>

### Run the installer on the database server

```sh
curl -fsSL https://rowsafe.sh | sudo sh
```

It prints a link. Open it, check the code matches your terminal, pick your organization and click **Approve**.

<Callout title="From the dashboard">
  **Servers** → **Add a server** gives the same command with a one-time token in it. Nothing to approve.
</Callout>

Then answer its questions:

1. **Your bucket.** Paste the bucket URL, access key ID and secret. It tests the bucket and tells you if something is wrong.
2. **The encryption passphrase.** It generates one and shows it once. Save it, then type its last 4 characters.
3. **Your database.** It finds PostgreSQL and suggests a name. Press Enter.
4. **The plan.** It shows what it will change and asks `Turn on backups for app now? [Y/n]`.

<Callout type="warn" title="Save the passphrase before you continue">
  Put it in your password manager now. Without it, no backup can be restored, and nobody can recover it, Rowsafe included.
</Callout>

Keys and passphrase stay on the server, in `/etc/rowsafe/agent.env`. Rowsafe never sees them.

</Step>
<Step>

### Restart PostgreSQL, now or later

Backups need one PostgreSQL restart. It takes seconds; open connections drop and your apps reconnect.

<Tabs items={["Restart now", "Restart later"]}>
<Tab value="Restart now">

Answer `y` to `Restart PostgreSQL now?`. You'll see:

```text
✓ app is protected. The first full backup is running.
```

</Tab>
<Tab value="Restart later">

Press Enter. Restart when it suits you:

```sh
sudo systemctl restart postgresql
```

Rowsafe notices and finishes the setup by itself.

</Tab>
</Tabs>

It also asks two questions:

- **Restart from the dashboard?** Adds a **Restart PostgreSQL now** button. It only restarts when someone clicks and confirms.
- **Manage PgBouncer?** For [connection pooling](/docs/guides/connection-pooling). Nothing installs until someone turns pooling on.

</Step>
</Steps>

Done. The database shows up in the dashboard under **Databases**.

## What happens next

Rowsafe now runs by itself. The first full backup starts right away.

| When (UTC) | What |
|---|---|
| Continuously | **Rewind**: every change saved, at most about a minute behind |
| Sundays 01:00 | Full backup |
| Monday to Saturday 01:00 | Differential backup |
| Sundays 21:15 | **Proof**: a restore test (or click **Run Proof now** after the first backup) |
| Every minute | **Pulse**: health checks and alerts, plus an email every Monday |

- Two full backups are kept: about two weeks to [restore to any second](/docs/guides/restore). Change it in the database's settings or with [`rowsafe set`](/docs/reference/cli#database-settings).
- A recent backup plus a passing Proof means [protected](/docs/concepts/protection-status).
- **Turn on alerts:** **Settings** → **Alerts and notifications** (email, Slack, Discord, webhooks: [Monitoring and alerts](/docs/guides/monitoring)).

## Install the CLI and log in

Optional, for scripts, CI and AI agents. On your own computer (macOS or Linux, no `sudo`):

```sh
curl -fsSL https://rowsafe.sh/cli | sh
rowsafe login
```

Run the installer again to update. [More ways to install](/docs/reference/cli#install).

```sh
rowsafe status app      # is it protected?
rowsafe proof app       # run Proof now
rowsafe pulse app       # health score and findings
```

Add another server over SSH, nothing to copy: `rowsafe hosts add root@203.0.113.10` ([how](/docs/guides/adopt#run-the-installer)).
