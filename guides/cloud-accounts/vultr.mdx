---
title: Connect Vultr
description: Turn on Vultr API access and give Rowsafe the key so it can create database servers there.
---

To [create servers for you](/docs/guides/create-a-server) in Vultr, Rowsafe needs your Vultr **API key**. It takes about two minutes.

## Get the API key

<Steps>
<Step>

### Choose the account

A Vultr key reaches everything its user can, in the whole account. If the account runs other servers, use a separate Vultr account, or a [sub-user's key](#limit-what-the-key-can-do).

</Step>
<Step>

### Turn on API access

Sign in to [Vultr](https://console.vultr.com), open the account menu (top right), choose **API Access** and click **Enable API Access**. Click **Copy**, tick **I have successfully copied the key** and click **Finalize Key Generation**. Vultr shows the key only once.

</Step>
<Step>

### Allow Rowsafe's address

Under **Access Control List**, click **Add IP to Allowlist** and add Rowsafe's address (the dashboard shows it when you connect). Or turn on **Any IPv4** and **Any IPv6**. Until then, Vultr refuses Rowsafe.

</Step>
<Step>

### Paste it into Rowsafe

In the dashboard, open **Settings → Cloud accounts** (or **Create a server for me**) and click **Connect a cloud account**. Choose **Vultr**, paste the key into **API key**, name the account and click **Connect**.

</Step>
</Steps>

Rowsafe checks the key first, without creating anything that costs money.

## What access this gives Rowsafe

**Whatever the key's user can do, in the whole account.** Vultr keys can't be limited to some servers. Rowsafe only touches what it creates:

- **servers** (Debian 13), tagged `rowsafe`, only when someone clicks and confirms;
- **firewall groups** named `rowsafe-…`, one per server, letting in only your addresses;
- **SSH keys**, only the ones you give it. Never its own.

See [what Rowsafe does with your cloud account](/docs/guides/create-a-server#what-rowsafe-does-with-your-cloud-account).

### Limit what the key can do

Create a **sub-user** (Account, **Users**) with only **Manage Servers**, **Provisioning** and **Manage Firewall**. Turn on API access for it and use its key.

## Revoke it

- **In Vultr:** **API Access**: delete the key or turn API access off. It stops working at once.
- **In Rowsafe:** **Settings → Cloud accounts**, **Remove** (once its servers are deleted). Nothing in Vultr changes.

Your servers keep running and stay protected. Resize, firewall changes and deletes then happen in the Vultr console.

## Good to know

- Prices are Vultr's own, shown "from" (some locations, like São Paulo, cost more). Your Vultr bill is what counts.
- **Resizing only goes up**, to a bigger plan with a bigger disk. The restart is a power cut (Vultr has no clean shutdown); committed data is safe.
- New accounts can have only a few servers. If you reach the limit, ask Vultr support to raise it.
- Vultr sets a root password on each server, shown in its console. Rowsafe never reads it, and SSH is open only to the addresses you add.
- To check the key, Rowsafe creates an empty, free firewall group (`rowsafe-key-check-…`) and deletes it right away.
