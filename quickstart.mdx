---
title: Quickstart
description: Protect your first PostgreSQL database in about 10 minutes. Create a storage bucket, run one command on your server, and answer its questions.
---

This guide protects one PostgreSQL server. You create a storage bucket, run one command on the server, and answer a few questions. Nothing changes until you say yes. You don't need to be a database expert: new words are in the [Glossary](/docs/glossary).

**You need:**

- A Linux server running PostgreSQL 13 to 18 on Debian 12/13 or Ubuntu 22.04/24.04, with `sudo`. (PostgreSQL in Docker? See [Run the agent in Docker](/docs/guides/docker).)
- A storage bucket for the backups: Cloudflare R2 (10 GB free), Backblaze B2, Amazon S3, Wasabi, DigitalOcean Spaces or any S3-compatible storage.
- A few seconds of downtime for one PostgreSQL restart, now or later, when it suits you.

<Callout title="Production database?">
  This is the short version. For a server that matters, follow [Adopt an existing database](/docs/guides/adopt): it adds the preflight checks, secret handling and rollback plan.
</Callout>

<Steps>
<Step>

### Create an account

[Sign up](https://app.rowsafe.sh/sign-up). The Free plan protects one server with up to three databases, with every feature.

</Step>
<Step>

### Create a bucket and an access key

Create a **private**, empty bucket, for example `app-rowsafe`, and an access key that can read, write and delete **only in that bucket**. Keep three things at hand:

- the **bucket URL**, for example Cloudflare R2's "S3 API" URL, `https://<account-id>.r2.cloudflarestorage.com/app-rowsafe`;
- the **access key ID**;
- the **secret**.

[Set up backup storage](/docs/guides/storage) shows where to find each of them, for every provider.

</Step>
<Step>

### Copy the install command

In the dashboard, open **Servers**, then **Add a server**. It shows the install command with a one-time enrollment token (`rse_...`), valid for one hour.

</Step>
<Step>

### Run it on the database server

```sh
curl -fsSL https://rowsafe.sh | sudo sh -s rse_...
```

It installs the agent (after checking its signature), then asks a few questions in your terminal:

1. **Your bucket.** Paste the bucket URL. Rowsafe works out the provider, region and bucket from it. Then paste the access key ID and the secret. It tests the bucket: it writes, reads back and deletes a small file. If something is wrong, it tells you what and lets you fix it.
2. **The encryption passphrase.** It generates a strong one and shows it once. Save it, then type its last 4 characters to confirm.
3. **Your database.** It finds PostgreSQL on the server and suggests a name. Press Enter to accept it:

   ```text
   Found PostgreSQL 18 on port 5432 (1.2 GB; databases: app)
   Name it in Rowsafe [app]:
   ```

4. **The plan.** It shows what it will change, in plain words, and asks:

   ```text
   Nothing changes until you say yes. Turn on backups for app now? [Y/n]
   ```

<Callout type="warn" title="Save the passphrase before you continue">
  Put the passphrase in your password manager **before** the first backup. Without it, no backup can ever be restored, and nobody can recover it, Rowsafe included.
</Callout>

Your keys and passphrase stay on the server, in `/etc/rowsafe/agent.env`. Rowsafe never sees them.

</Step>
<Step>

### Restart PostgreSQL, now or later

Turning on backups needs one PostgreSQL restart. It takes a few seconds: open connections are dropped, and your apps reconnect. The installer asks:

```text
Restart PostgreSQL now? [y/N]
```

<Tabs items={["Restart now", "Restart later"]}>
<Tab value="Restart now">

Answer `y`. Rowsafe restarts PostgreSQL, checks that changes reach your bucket, and prints:

```text
✓ app is protected. The first full backup is running.
```

</Tab>
<Tab value="Restart later">

Press Enter. Restart PostgreSQL when it suits you, for example in a quiet hour:

```sh
sudo systemctl restart postgresql
```

Rowsafe notices the restart by itself and finishes the setup. Nothing else to do.

</Tab>
</Tabs>

The installer also asks whether to allow restarting PostgreSQL from the Rowsafe dashboard. If you allow it, the database's page gets a **Restart PostgreSQL now** button. It restarts only when someone clicks it and confirms.

</Step>
</Steps>

That's it. The database now shows up in the dashboard under **Databases**.

## What happens next

Rowsafe now runs on its own:

- **The first full backup** starts right away.
- **Rewind** is on: every change is saved to your bucket, at most about a minute behind. You can restore to any second from the first backup on, in one click: see [Restore a database](/docs/guides/restore).
- **Proof**, the weekly restore test, restores a copy of your database and checks it. The first one runs on Sunday. To run it sooner, wait for the first backup to finish, then click **Run Proof now** on the database's page.
- **Pulse** watches the database's health and alerts you about problems. Every Monday, "Your weekly Pulse" arrives by email.

By default, in UTC:

| When | What |
|---|---|
| Continuously | Every change is saved to your bucket, at most about a minute behind |
| Sundays 01:00 | Full backup |
| Monday to Saturday 01:00 | Differential backup |
| Sundays 21:15 | Proof (restore test) |

It keeps two full backups, so you can restore to any point in about the last two weeks. You can change the schedules and retention in the database's settings, or with [`rowsafe set`](/docs/reference/cli#database-settings).

Once there is a recent backup and a passing Proof, the database counts as [protected](/docs/concepts/protection-status).

**Set up alerts** so you hear about problems: in the dashboard under **Settings**, then **Alerts and notifications**. See [Monitoring and alerts](/docs/guides/monitoring) for email, Slack, Discord and webhooks.

## Install the CLI and log in

You don't need the CLI to get started. It is useful for scripts, CI and AI agents. It is a single binary for macOS and Linux. Run this on your own computer:

<Tabs items={["macOS (Apple silicon)", "macOS (Intel)", "Linux (x86-64)", "Linux (ARM64)"]}>
<Tab value="macOS (Apple silicon)">

```sh
curl -fsSLo rowsafe https://github.com/rowsafe/rowsafe/releases/latest/download/rowsafe-darwin-arm64
chmod +x rowsafe && sudo mv rowsafe /usr/local/bin/
```

</Tab>
<Tab value="macOS (Intel)">

```sh
curl -fsSLo rowsafe https://github.com/rowsafe/rowsafe/releases/latest/download/rowsafe-darwin-amd64
chmod +x rowsafe && sudo mv rowsafe /usr/local/bin/
```

</Tab>
<Tab value="Linux (x86-64)">

```sh
curl -fsSLo rowsafe https://github.com/rowsafe/rowsafe/releases/latest/download/rowsafe-linux-amd64
chmod +x rowsafe && sudo mv rowsafe /usr/local/bin/
```

</Tab>
<Tab value="Linux (ARM64)">

```sh
curl -fsSLo rowsafe https://github.com/rowsafe/rowsafe/releases/latest/download/rowsafe-linux-arm64
chmod +x rowsafe && sudo mv rowsafe /usr/local/bin/
```

</Tab>
</Tabs>

Then log in. This opens the dashboard in your browser, where you confirm a code:

```sh
rowsafe login
```

Over SSH, or with `--no-browser`, open the printed link on any device. Then, for example:

```sh
rowsafe status app      # is it protected?
rowsafe proof app       # run Proof now
rowsafe pulse app       # health score and findings
```

`rowsafe hosts enroll-token` also prints the install command, if you prefer the terminal to the dashboard.
