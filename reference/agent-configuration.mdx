---
title: Agent configuration
description: Every setting of the Rowsafe agent and its installer, the files it installs, and its commands.
---

The agent reads its configuration from environment variables. On a server, systemd loads them from `/etc/rowsafe/agent.env` (owned by `postgres`, mode 0600). In Docker, they come from the `env_file` of the agent service.

In `agent.env`, values are single-quoted and must not contain single quotes or newlines. After a change, run the installer again (it self-tests first) or `sudo systemctl restart rowsafe-agent`.

## Where backups go

| Variable | Default | |
|---|---|---|
| `ROWSAFE_STORAGE` | `own` | `rowsafe` for [Rowsafe Storage](/docs/guides/rowsafe-storage) (coming soon, not available yet): the location and short-lived credentials come from Rowsafe, and the `ROWSAFE_REPO_S3_*` settings below are not used (`ROWSAFE_REPO_CIPHER_PASS` still is). `own` for your bucket. |

## Bucket (repository)

For your own bucket. The installer fills these in from the bucket URL and keys you paste. Set them yourself for installs without questions.

| Variable | Default | |
|---|---|---|
| `ROWSAFE_REPO_S3_ENDPOINT` | **required** | Host name without `https://`, e.g. `<account-id>.eu.r2.cloudflarestorage.com`. |
| `ROWSAFE_REPO_S3_BUCKET` | **required** | A private bucket. |
| `ROWSAFE_REPO_S3_KEY` | **required** | Access key ID of a token that can read and write only this bucket. |
| `ROWSAFE_REPO_S3_KEY_SECRET` | **required** | Its secret. |
| `ROWSAFE_REPO_CIPHER_PASS` | **required** | Encryption passphrase, at least 20 characters. **Store it in your secret manager before the first backup.** |
| `ROWSAFE_REPO_S3_REGION` | `auto` | `auto` for R2. |
| `ROWSAFE_REPO_S3_URI_STYLE` | `path` | `path` or `host`. |
| `ROWSAFE_REPO_PATH_PREFIX` | `/rowsafe` | Each database lives under `<prefix>/<name>` in the bucket. |
| `ROWSAFE_REPO_S3_PORT` | `443` | For other S3-compatible stores. |
| `ROWSAFE_REPO_S3_CA_FILE` | system store | Absolute path to a PEM bundle to trust instead, e.g. for a private MinIO. |
| `ROWSAFE_REPO_S3_VERIFY_TLS` | `true` | `false` turns off certificate checks. For tests only. |

Never change the passphrase, bucket or prefix of a repository that holds backups. See [Change the configuration](/docs/guides/agent-updates#change-the-configuration).

## Second copy

Optional: a second bucket that gets the backups and the change log too, set up with `--add-storage` (see [Keep a second copy of your backups](/docs/guides/second-copy)). Every setting of the bucket above exists with `ROWSAFE_REPO2_` instead of `ROWSAFE_REPO_`, with the same defaults: `ROWSAFE_REPO2_S3_ENDPOINT`, `_S3_BUCKET`, `_S3_KEY`, `_S3_KEY_SECRET` and `ROWSAFE_REPO2_CIPHER_PASS` are needed, `_S3_REGION`, `_S3_URI_STYLE`, `_PATH_PREFIX`, `_S3_PORT`, `_S3_CA_FILE` and `_S3_VERIFY_TLS` are optional.

| Variable | Default | |
|---|---|---|
| `ROWSAFE_REPO2_CIPHER_PASS` | | Its own passphrase, at least 20 characters. Not the first bucket's. |
| `ROWSAFE_REPO2_QUEUE_DIR` | `/var/lib/rowsafe/copy2-queue` | Where change log files wait to be sent to the second bucket (at most 256 files per database). |

If some are missing, the agent keeps working with the first bucket only and says what is missing in its log and on the Storage page. The agent writes the second copy's pgBackRest configuration to `/etc/rowsafe/pgbackrest/<name>.copy2.conf`.

## Connection to Rowsafe

| Variable | Default | |
|---|---|---|
| `ROWSAFE_ENROLL_TOKEN` | | The one-time enrollment token (`rse_...`). Only needed until the first start; delete it afterwards. |
| `ROWSAFE_URL` | `https://api.rowsafe.sh` | The API URL. Leave it unset. |
| `ROWSAFE_AUTO_UPDATE` | `true` | `false` (or `0`, `no`, `off`) turns self-update off. Any value other than true/false stops the agent from starting. Always off in Docker. |
| `ROWSAFE_POLL_INTERVAL` | `5s` | How often an idle agent asks for work. |
| `ROWSAFE_HEARTBEAT_INTERVAL` | `30s` | How often it reports in. |

## PostgreSQL and the server

| Variable | Default | |
|---|---|---|
| `ROWSAFE_PG_USER` | `postgres` | The database role the agent connects as, over the Unix socket. Must be a superuser. |
| `ROWSAFE_PG_BIN_DIR` | `/usr/lib/postgresql/%d/bin` | PostgreSQL server binaries, used by Proof. `%d` is the major version. |
| `ROWSAFE_PGBACKREST_BIN` | `/usr/bin/pgbackrest` | pgBackRest, also used in `archive_command`. |
| `ROWSAFE_DRILL_DIR` | `/var/lib/rowsafe/drills` | Scratch space for Proof, the weekly restore test (internally a drill). |
| `ROWSAFE_DRILL_PORT` | `55432` | Names the Unix socket of Proof's scratch cluster, and of Rewind copies. They never listen on TCP. |
| `ROWSAFE_REWIND_DIR` | `/var/lib/rowsafe/rewind` | Where [Rewind](/docs/guides/restore) restores copies: about 1.3 × the database size + 1 GiB free per copy. A short absolute path. |
| `ROWSAFE_DRILL_PRELOAD` | `auto` | `auto`: start Proof's scratch cluster without production's `shared_preload_libraries`, and retry with them if needed. `production`: always load them. |
| `ROWSAFE_COPIES_DIR` | `/var/lib/rowsafe/copies` | Where [migration previews](/docs/guides/preview-migrations) and [safe copies](/docs/guides/safe-copies) are restored, one directory each. |
| `ROWSAFE_COPY_PORTS` | `55440-55539` | The TCP ports safe copies listen on. Allow them in your firewall for the addresses that connect. |
| `ROWSAFE_COPY_TLS_CERT`, `ROWSAFE_COPY_TLS_KEY` | | A certificate and key for safe copies, readable by the agent's user. Without them each copy makes its own self-signed certificate. |
| `ROWSAFE_PREVIEW_KEEP` | `1h` | How long a preview copy is kept so the next preview starts fast (`0` deletes it right away, at most `24h`). |
| `ROWSAFE_RESTORE_POINT_TIMEOUT` | `90s` | How long to wait for a Mark (restore point) to be archived, up to `4m`. |
| `ROWSAFE_MONITORING` | `true` | `false` turns metrics off. |
| `ROWSAFE_COLLECT_QUERY_TEXT` | `true` | `false` sends long-running queries without their text. |
| `ROWSAFE_LOGS` | `true` | `false`: the agent never reads PostgreSQL's log ([Logs](/docs/guides/logs)). |
| `ROWSAFE_STANDBY` | `on` | [Standby servers](/docs/guides/standby). `on`: this server pairs with the servers a person confirms in the dashboard. `pinned`: only with the key fingerprints in `ROWSAFE_STANDBY_PEERS`, so even a compromised Rowsafe can't pair a server of its own. `off`: it takes no part in standbys at all. |
| `ROWSAFE_STANDBY_PEERS` | | With `ROWSAFE_STANDBY=pinned`: comma-separated key fingerprints (`sudo -u postgres rowsafe-agent key` on each server) this server may send its bucket settings to or receive them from. |
| `ROWSAFE_CREATE_CLUSTER_ALLOW_FILE` | `/etc/rowsafe/create-cluster-allowed` | [Forks](/docs/guides/fork): the ports (`ports 5440-5499`) on which root allowed Rowsafe to create new PostgreSQL clusters. The installer writes it (`--allow-create-cluster`). |
| `ROWSAFE_CREATED_CLUSTERS_FILE` | `/etc/rowsafe/created-clusters` | The clusters created for forks (`PORT UNIT` per line), which Rowsafe may stop and start like those allowed with `--allow-restart`. Written by root. |

### MongoDB

| Variable | Default | |
|---|---|---|
| `ROWSAFE_MONGODB_URI` | | A whole connection string (`mongodb://user:password@host:port/?authSource=admin`) instead of the login the installer saves. For a single server; Docker sidecars usually use `ROWSAFE_MONGODB_HOST` and `rowsafe-agent mongodb login` instead. |
| `ROWSAFE_MONGODB_HOST` | `127.0.0.1` | Where MongoDB listens (the `mongo` service's name in Docker). |
| `ROWSAFE_MONGODB_ARCHIVE_INTERVAL` | `1m` | How often new oplog entries are copied to your bucket (1s to 10m). |
| `ROWSAFE_MONGODB_BIN_DIR` | `PATH`, then `/usr/bin` | Where `mongodump`, `mongorestore` and `mongod` are. |

See [Protect MongoDB](/docs/guides/mongodb).

### Files

| Variable | Default | |
|---|---|---|
| `ROWSAFE_RESTIC_BIN` | `/usr/local/lib/rowsafe/restic` | restic, for [Files](/docs/guides/files). Falls back to `restic` on the `PATH`. |
| `ROWSAFE_FILES_CACHE_DIR` | `<state dir>/files-cache` | restic's cache. |
| `ROWSAFE_FILES_STAGING_DIR` | `<state dir>/files-staging` | Where restores are staged before they are put in place. The root helper expects the default. |
| `ROWSAFE_FILES_ALLOW_FILE` | `/etc/rowsafe/files-allowed` | The exact folders root allowed Rowsafe to read and restore into, with their owner (`PATH UID` lines; `--files PATH --allow-files`). The agent only reads it. |
| `ROWSAFE_FILES_MOUNT_DIR` | `/rowsafe-files` | Docker: where volumes to back up are mounted. |

The installer, the systemd unit and the update guard assume the default directories (`ROWSAFE_STATE_DIR`, `ROWSAFE_CONFIG_DIR`, `ROWSAFE_LOG_DIR`, `ROWSAFE_INSTALL_DIR`). Don't change them on a server.

## Connection pooling

For [Connection pooling](/docs/guides/connection-pooling) (PgBouncer). All are optional.

| Variable | Default | |
|---|---|---|
| `ROWSAFE_POOLER_STATS_URL` | | A PgBouncer that Rowsafe doesn't manage, to monitor: its admin console as a `postgres://` URL, e.g. `postgres://stats:PASSWORD@pgbouncer:6432/pgbouncer` in Docker. Rowsafe reads its statistics and never changes it. |
| `ROWSAFE_POOLER_DATABASE` | | With `ROWSAFE_POOLER_STATS_URL`: the name in Rowsafe of the database that PgBouncer serves. Only needed when the agent has more than one database. |
| `ROWSAFE_POOLER_ALLOW_FILE` | `/etc/rowsafe/pooler-allowed` | The PostgreSQL ports root allowed Rowsafe to put PgBouncer in front of. Written by the installer (`--allow-pooler`). |
| `ROWSAFE_POOLER_DIR` | `<ROWSAFE_STATE_DIR>/pooler` | Where the agent writes requests for the root helper. |
| `ROWSAFE_POOLER_RESULT_DIR` | `/run/rowsafe-pooler` | Where the root helper writes its answers. |
| `ROWSAFE_POOLER_SOCKET_DIR` | `/var/run/postgresql` | The directory of PgBouncer's Unix socket, for its admin console. |
| `ROWSAFE_POOLER_USERLIST` | `/etc/pgbouncer/userlist.txt` | PgBouncer's user list, where the agent reads the password of `rowsafe_pgbouncer`. |

The root helper and its systemd units use the default paths, so on a server, leave all but the first two unset. Paths must be absolute.

## Installer

```sh
curl -fsSL https://rowsafe.sh | sudo sh -s rse_...                   # install and set up, with questions
curl -fsSL https://rowsafe.sh | sudo sh -s rse_... --protect app     # the same, without questions
curl -fsSL https://rowsafe.sh | sudo sh                              # run again: update, re-test, start
curl -fsSL https://rowsafe.sh | sudo sh -s -- --uninstall            # options alone go after `sh -s --`
```

`https://rowsafe.sh/install` serves the same script.

| Option | |
|---|---|
| `rse_...` | The enrollment token. `ROWSAFE_ENROLL_TOKEN=rse_...` in the environment works too. |
| `--protect NAME` | Set up the database without questions: register it as `NAME`, plan and apply. Never restarts PostgreSQL. The storage settings must then be in the environment (`ROWSAFE_REPO_*`). |
| `--no-setup` | Install the agent and set up storage only. Skip finding and protecting the database: add it later from the dashboard or with `rowsafe adopt`. |
| `--allow-restart` | Allow restarting PostgreSQL from the Rowsafe dashboard, without asking. Only when someone clicks **Restart** and confirms. |
| `--no-allow-restart` | Don't allow it, without asking. |
| `--files PATH` | Back up the folder `PATH` (uploads, media) with the database, without asking; repeat for several. Gives the agent's user read-only access to it (ACL) if it needs it. See [Back up and restore files](/docs/guides/files). |
| `--allow-files` | Allow Rowsafe to put restored files back into the folders protected with `--files` (as the folder's owner), and those folders only: they are listed with their owner in `/etc/rowsafe/files-allowed`. A folder added later in the dashboard needs `--files` and that folder once more. Only when someone asks and confirms. |
| `--no-allow-files` | Don't allow it, without asking. |
| `--no-files` | Don't ask about folders with uploads. |
| `--allow-pooler` | Allow Rowsafe to install and manage PgBouncer ([connection pooling](/docs/guides/connection-pooling)), without asking. Nothing is installed until someone turns pooling on and confirms. |
| `--no-allow-pooler` | Don't allow it, without asking. A PgBouncer Rowsafe already set up keeps running, but Rowsafe can no longer change it. |
| `--allow-pooler-public` | With `--allow-pooler`: also let PgBouncer listen on every address when someone chooses "public" for it. Without it, PgBouncer listens only on this server and its private network. |

| `--allow-restart` | Allow Rowsafe to restart or stop PostgreSQL when you ask, without asking at install: **Restart**, and **Rewind the whole database**, in the dashboard. Only when someone clicks and confirms. Installs the root helper `rowsafe-pg-restart`. |
| `--no-allow-restart` | Don't allow it, without asking, and remove the helper. Also turns off the three options below. |
| `--allow-updates` | Allow installing PostgreSQL minor updates and upgrading PostgreSQL from Rowsafe, without asking. Only when someone clicks **Update** or **Upgrade** and confirms. Needs `--allow-restart`. See [Update and upgrade PostgreSQL](/docs/guides/updates). |
| `--no-allow-updates` | Don't allow it, without asking. |
| `--allow-security-updates` | Allow installing the server's security updates from Rowsafe, without asking. Needs `--allow-restart`. |
| `--no-allow-security-updates` | Don't allow it, without asking. |
| `--allow-reboot` | Allow rebooting the server from Rowsafe, without asking. Needs `--allow-restart`. |
| `--no-allow-reboot` | Don't allow it, without asking. |
| `--allow-firewall` | Allow Rowsafe to limit who can reach PostgreSQL's port with the server's firewall (nftables), without asking. Only PostgreSQL's port, never SSH; only when someone chooses the addresses under [Security](/docs/guides/security#the-firewall) and confirms. |
| `--no-allow-firewall` | Don't allow it, without asking; removes Rowsafe's firewall rule and helper. |
| `--mongodb-replica-set` | MongoDB: turn a standalone server into a replica set of one without asking (one MongoDB restart). Restoring to any second needs it. |
| `--no-mongodb-replica-set` | MongoDB: never do that. |
| `--allow-create-cluster` | Allow Rowsafe to create a new PostgreSQL cluster (on a free port in 5440-5499) when someone [forks a database](/docs/guides/fork) to this server and confirms, without asking. Debian and Ubuntu (`pg_createcluster`). |
| `--no-allow-create-cluster` | Don't allow it, without asking. Clusters created earlier stay. |
| `--setup-storage` | Set up (or change) the backup storage, even if it is configured. |
| `--storage PROVIDER` | Skip the "where" question: `rowsafe` ([Rowsafe Storage](/docs/guides/rowsafe-storage), coming soon; works without a terminal too), or a bucket provider: `r2`, `b2`, `s3`, `wasabi`, `spaces` or `s3-compatible`. |
| `--no-prompt` | Never ask questions, even on a terminal. |
| `--check-storage` | Test the backup storage in `agent.env` (your bucket, or Rowsafe Storage through the agent, and the second copy's, if there is one). Change nothing. |
| `--add-storage` | Add a second copy in another bucket, with questions like the first storage, or move it to another bucket. Without a terminal, takes `ROWSAFE_REPO2_*` from the environment and tests it before saving. |
| `--remove-second-copy` | Stop sending backups to the second copy. Its bucket is left as it is. |
| `--download-only DIR` | Download and verify the agent into `DIR`; install nothing. Needs no root. |
| `--uninstall` | Stop and remove the service and `/opt/rowsafe`. Keep the configuration, state and logs. |
| `--uninstall --purge` | Also delete `/etc/rowsafe`, `/var/lib/rowsafe`, `/var/log/rowsafe` and the logrotate file. Refused while PostgreSQL still archives with Rowsafe's configuration. |
| `-h`, `--help` | Help. |

| Environment variable | |
|---|---|
| `ROWSAFE_VERSION=1.2.3` | Install exactly this version instead of the channel's latest. |
| `ROWSAFE_CHANNEL=stable` | The channel to install from. Later updates follow the host's channel in Rowsafe. |
| `ROWSAFE_ALLOW_DOWNGRADE=1` | Allow `ROWSAFE_VERSION` to be older than the installed version. |
| `ROWSAFE_ALLOW_UNSUPPORTED_OS=1` | Try an OS other than Debian 12/13 or Ubuntu 22.04/24.04. |

The installer also copies these settings from its environment into `agent.env`, without printing them: `ROWSAFE_URL`, `ROWSAFE_ENROLL_TOKEN`, `ROWSAFE_STORAGE`, every `ROWSAFE_REPO_*` and `ROWSAFE_REPO2_*` setting above, `ROWSAFE_AUTO_UPDATE`, `ROWSAFE_PG_USER`, `ROWSAFE_PG_BIN_DIR`, `ROWSAFE_PGBACKREST_BIN`, `ROWSAFE_DRILL_DIR`, `ROWSAFE_DRILL_PORT`, `ROWSAFE_POLL_INTERVAL` and `ROWSAFE_HEARTBEAT_INTERVAL`. Set anything else by editing the file.

What the installer does:

1. Checks the system: root, Debian 12/13 or Ubuntu 22.04/24.04, amd64 or arm64, a `postgres` user and PostgreSQL server binaries, OpenSSL 3.
2. Downloads the release manifest and its signature, verifies the **Ed25519 signature** with the key built into the installer, then checks the binary's size and SHA-256. If any check fails, nothing on the server changes.
3. Installs pgBackRest if it is missing: from apt.postgresql.org when that repository is configured, otherwise from your distribution. Installs [restic](https://restic.net) 0.19.1 for [Files](/docs/guides/files) from its GitHub release into `/usr/local/lib/rowsafe/restic`, checked against the SHA-256 published with the release (a mismatch installs nothing; your distribution's restic 0.17+ is used if GitHub can't be reached).
4. Installs the agent, the systemd unit and a logrotate file.
5. Sets up the storage if it isn't configured (questions below), and writes `agent.env`, keeping settings already in it.
6. If settings are missing, enables the service without starting it and lists what's missing. Otherwise self-tests the new agent, and only then starts or restarts it.
7. Unless you pass `--no-setup`, finds PostgreSQL on the server and protects it (questions below, or `--protect NAME`).

### The questions it asks

On a terminal, a first install asks:

| Question | |
|---|---|
| Where should backups go? | Only when Rowsafe offers [Rowsafe Storage](/docs/guides/rowsafe-storage). 1 (the default): Rowsafe Storage, and the bucket questions below are skipped. 2: your own bucket. |
| Paste your bucket URL | For example Cloudflare R2's "S3 API" URL, `https://<account-id>.r2.cloudflarestorage.com/<bucket>`. The provider, endpoint, region and bucket are detected from it. See [Set up backup storage](/docs/guides/storage). |
| Access key ID, secret | Typed hidden. Then it tests the bucket: it writes, reads back and deletes a small file. |
| Encryption passphrase | It generates one and shows it once (or takes your own). You type its last 4 characters to confirm you saved it. |
| `Name it in Rowsafe [app]:` | After `Found PostgreSQL 18 on port 5432 (1.2 GB; databases: app)`. Enter accepts the suggestion. |
| `Turn on backups for app now? [Y/n]` | After the plan, in plain words. Nothing changes until you say yes. |
| `Allow restarting PostgreSQL from the Rowsafe dashboard? [Y/n]` | Only when someone clicks **Restart** and confirms. |
| `Allow Rowsafe to install and manage PgBouncer? ... [Y/n]` | Nothing is installed now: only when someone turns [connection pooling](/docs/guides/connection-pooling) on and confirms. |

| `Allow Rowsafe to install PostgreSQL updates when you click Update? [Y/n]` | Only when restarts are allowed. Minor updates and major upgrades, only when someone confirms; a Mark is saved first. |
| `Allow Rowsafe to install this server's security updates when you click Install? [y/N]` | Only when restarts are allowed. |
| `Allow Rowsafe to reboot this server when you click Reboot? [y/N]` | Only after a yes to security updates. |
| `Allow Rowsafe to limit who can reach PostgreSQL's port with the firewall? [y/N]` | Only when nftables is installed. Only PostgreSQL's port, never SSH; only when someone picks the addresses in the dashboard and confirms. See [the firewall](/docs/guides/security#the-firewall). |
| `Allow Rowsafe to create a new PostgreSQL cluster here when you fork a database to this server? [Y/n]` | For [forks](/docs/guides/fork): only when someone confirms a fork, on ports 5440-5499. Asked once, on Debian and Ubuntu, only when restarts are allowed. |
| `Restart PostgreSQL now? [y/N]` | Only if a setting needs a restart. Yes: it restarts, checks that changes reach the bucket, and the first full backup starts. No: restart when it suits you; Rowsafe notices by itself. |
| `Does this app store uploads on this server? Rowsafe found /srv/app/storage/app (2.3 GiB, ...). Back it up with app, so a restore brings back both? [Y/n]` | For up to three folders that look like uploads. See [Back up and restore files](/docs/guides/files). |
| `Allow Rowsafe to put restored files back into /srv/app/storage/app, as the folder's owner? [Y/n]` | Once a folder is protected; it names exactly the folders it allows. Only when someone asks and confirms. |

Secrets are never printed, and nothing is saved until you have answered the storage questions. Without a terminal, or with `--no-prompt`, it asks nothing: set the storage settings in the environment, and use `--protect NAME` to protect the database. Changes the installer makes show up in the [audit log](/docs/guides/teams#audit-log) as `installer on <hostname>`.

## Files on the server

```text
/opt/rowsafe/                          postgres 0755
  rowsafe-agent -> versions/<v>/...    the binary systemd runs; swapped on update
  versions/<v>/rowsafe-agent           current and previous version
  bin/rowsafe-agent-guard              root 0755; rolls back an update that keeps crashing
/etc/rowsafe/                          root:postgres 0750
  agent.env                            postgres 0600; settings and secrets
  pgbackrest/<name>.conf               postgres 0600; generated, local edits are overwritten
/var/lib/rowsafe/                      postgres 0700; identity, state, running Proof copies
  files.json                           the protected folders' settings and state (Files)
  files-cache/, files-staging/         restic's cache; restores staged before they are put in place
  files-restored/<id>/                 restored files Rowsafe could not put back into their folder
  storage-credentials.json             postgres 0600; Rowsafe Storage only: the current short-lived credentials
/var/log/rowsafe/                      postgres 0700; pgBackRest logs, rotated daily, 14 kept
/usr/local/lib/rowsafe/restic          root 0755; restic, for Files
/etc/rowsafe/files-allowed             root 0644; "PATH UID" per folder Rowsafe may read and restore into (--allow-files)
/etc/systemd/system/rowsafe-agent.service
/etc/logrotate.d/rowsafe

Only when you allowed restarts, updates, security updates or reboots:
/etc/rowsafe/restart-allowed           root 0644; "PORT UNIT" per cluster Rowsafe may restart or stop
/etc/rowsafe/updates-allowed           root 0644; postgresql, security, reboot: what Rowsafe may do
/usr/local/lib/rowsafe/rowsafe-pg-restart   root 0755; the root helper
/etc/systemd/system/rowsafe-pg-restart.{service,path}   restarts, stops, starts
/etc/systemd/system/rowsafe-pg-update.{service,path}    updates, upgrades, reboots
/var/lib/rowsafe-pg-restart/           root 0700; what an upgrade keeps for undo
```

With `--allow-pooler`, the installer also writes `/etc/rowsafe/pooler-allowed` and the `rowsafe-pooler` systemd units: see [Connection pooling](/docs/guides/connection-pooling#files-on-the-server) for the files PgBouncer uses.

**Logs:** `journalctl -u rowsafe-agent` (JSON lines), and `/var/log/rowsafe/<name>-<command>.log`. Each task's log, including pgBackRest's output, is also in `rowsafe task ID`.

**The systemd unit** runs the agent as `postgres` with `NoNewPrivileges`, a read-only system, a private `/dev`, no capabilities and restricted address families. It is rewritten by the installer: put local changes in a drop-in (`sudo systemctl edit rowsafe-agent`).

**The files helper** (only with `--allow-files`): `rowsafe-files-helper.{service,path}` in `/etc/systemd/system`, with a drop-in (`rowsafe-files-helper.service.d/folders.conf`) that lets it write only into the folders in `/etc/rowsafe/files-allowed`. It runs the same script as the root helper, in its own sandbox, and keeps its private copy and cooldowns in `/var/lib/rowsafe-files-helper`. See [Files](/docs/guides/files#permissions-on-the-server).

**The firewall helper** (only with `--allow-firewall`): `/usr/local/lib/rowsafe/rowsafe-firewall` (root 0755), started by `rowsafe-firewall.path` when the agent asks, and loaded at boot by `rowsafe-firewall-restore.service`. It changes only its own nftables table (`inet rowsafe`), only for the ports in `/etc/rowsafe/firewall-allowed` (root 0644), and keeps its rules in `/var/lib/rowsafe-firewall`.

## Agent commands

```text
rowsafe-agent run         enroll if needed, then run tasks (what systemd runs)
rowsafe-agent inspect     print what the agent sees in PostgreSQL (read-only)
                          [--port 5432] [--socket-dir /var/run/postgresql] [--user postgres]
rowsafe-agent selftest    check the configuration, pgBackRest, Rowsafe and every database
rowsafe-agent storage test [--wait 60s]
                          write, read back and delete a test file in the backup storage
rowsafe-agent health      container health check (Docker)
rowsafe-agent files discover|access|list|add
                          the folders that go with a database (used by the installer)
rowsafe-agent mongodb status|login|initiate|save-uri --port 27017 [--admin-user NAME]
                          MongoDB: what the installer needs to know; create Rowsafe's
                          MongoDB user; start a replica set of one; save a login you made
rowsafe-agent unseal      decrypt a file Rowsafe wrote to your bucket (stdin to stdout)
rowsafe-agent version
```

Run the self-test exactly as the service would:

```sh
sudo systemd-run --quiet --wait --pipe --collect -p User=postgres \
  -p EnvironmentFile=/etc/rowsafe/agent.env /opt/rowsafe/rowsafe-agent selftest
```
