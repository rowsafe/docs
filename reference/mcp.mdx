Rowsafe speaks the [Model Context Protocol](https://modelcontextprotocol.io). AI assistants can read what the dashboard shows ("is everything backed up?", "why did this alert fire?", "what is blocking the app?") and, when you allow it, set Marks (restore points), run backups, Proof and checks, and ask you to approve changes to production. Nothing changes in production until an owner or admin approves it in the dashboard: see [Approvals](/docs/guides/approvals). The MCP tools are part of [Guard](/docs/guides/ai-agents), the safety net for AI agents.

| | Transport | Credentials | Write tools |
|---|---|---|---|
| `rowsafe mcp` | stdio, on your machine | The CLI's login, or `ROWSAFE_API_KEY` | Off by default. `--allow-restore-points` or `--allow-writes`. |
| `https://api.rowsafe.sh/mcp` | Streamable HTTP | **Sign in with Rowsafe** (OAuth), or `Authorization: Bearer rsk_...` (an API key). | API keys: always listed; a read-only key can't use them. Signed-in apps: `create_restore_point` if you allowed Marks, and the write tools and `request_change` if you allowed **Act for you**. |

For the safety-net workflow with coding agents, see [Use Rowsafe with AI agents](/docs/guides/ai-agents). To add Rowsafe to ChatGPT, Claude, Cursor, VS Code, Codex or Windsurf, see [Connect AI apps](/docs/guides/connect-ai-apps).

## Set up

<Tabs items={["Claude Code", "Claude Desktop", "Remote endpoint"]}>
<Tab value="Claude Code">

Log in with the CLI first (`rowsafe login`), then pick a mode:

```sh
# Read-only
claude mcp add rowsafe -- rowsafe mcp

# Read-only, plus Marks (what the Claude Code plugin uses)
claude mcp add rowsafe -- rowsafe mcp --allow-restore-points

# Also backups, Proof, checks, schedules, and asking you to approve changes to production
claude mcp add rowsafe -- rowsafe mcp --allow-writes

# A specific key instead of your login, in every project
claude mcp add --scope user rowsafe -e ROWSAFE_API_KEY=rsk_... -- rowsafe mcp
```

`--scope project` writes `.mcp.json` into your repository for everyone: don't put a key in it. Use the stdio form (each developer's own login) there.

</Tab>
<Tab value="Claude Desktop">

Claude Desktop runs local servers from its config file: `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS, `%APPDATA%\Claude\claude_desktop_config.json` on Windows (**Settings**, **Developer**, **Edit Config**).

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "rowsafe": {
      "command": "/usr/local/bin/rowsafe",
      "args": ["mcp"],
      "env": {
        "ROWSAFE_API_KEY": "rsk_..."
      }
    }
  }
}
```

Use the absolute path of `rowsafe` (`which rowsafe`): Desktop doesn't use your shell's `PATH`. Add `"--allow-restore-points"` or `"--allow-writes"` to `args` for write tools. Restart Claude Desktop afterwards.

Or use a remote connector instead (**Settings**, **Connectors**, **Add custom connector**, `https://api.rowsafe.sh/mcp`), where you sign in with Rowsafe, with no key or local binary. See [Connect AI apps](/docs/guides/connect-ai-apps).

</Tab>
<Tab value="Remote endpoint">

No local binary needed. Sign in with Rowsafe:

```sh
claude mcp add --transport http rowsafe https://api.rowsafe.sh/mcp
```

Then run `/mcp` in Claude Code and choose **Authenticate**. Or connect with an API key, for CI:

```sh
claude mcp add --transport http rowsafe https://api.rowsafe.sh/mcp --header "Authorization: Bearer rsk_..."
```

- Every request needs an OAuth access token or an API key. Use a [read-only key](/docs/guides/teams#api-keys) (`rowsafe api-keys create NAME --read-only`) for an assistant that must never change anything.
- The endpoint is stateless and answers with plain JSON.
- Tool calls wait at most 45 seconds.

</Tab>
</Tabs>

## Sign in with Rowsafe (OAuth)

The remote endpoint is an OAuth 2.1 protected resource, following the [MCP authorization specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) (2026-07-28). MCP clients discover everything from the first `401`; you only give them the URL. See [Connect AI apps](/docs/guides/connect-ai-apps) for each client.

| | |
|---|---|
| Protected resource metadata ([RFC 9728](https://www.rfc-editor.org/rfc/rfc9728)) | `https://api.rowsafe.sh/.well-known/oauth-protected-resource/mcp`, named in `WWW-Authenticate` on every `401` |
| Authorization server metadata ([RFC 8414](https://www.rfc-editor.org/rfc/rfc8414)) | `https://api.rowsafe.sh/.well-known/oauth-authorization-server` (issuer `https://api.rowsafe.sh`) |
| Client registration | Client ID metadata documents (an HTTPS `client_id`), or dynamic registration ([RFC 7591](https://www.rfc-editor.org/rfc/rfc7591)) at `/oauth/register`. Clients are public: no client secret. |
| Grant | Authorization code with PKCE, `S256` only. The response carries `iss` ([RFC 9207](https://www.rfc-editor.org/rfc/rfc9207)). |
| Redirect URIs | Exact match. Accepted: ChatGPT's, Claude's, VS Code's and Cursor's published callbacks, and loopback (`http://127.0.0.1`, `http://[::1]`, `http://localhost`, any port). |
| Resource ([RFC 8707](https://www.rfc-editor.org/rfc/rfc8707)) | `https://api.rowsafe.sh/mcp`. Tokens work on `/mcp` only. |
| Scopes | `rowsafe:read` (always), `rowsafe:marks` (optional, **Save Marks**: adds `create_restore_point`), `rowsafe:act` (optional, **Act for you**: adds the write tools, the copy tools and `request_change`). `offline_access` is accepted; other scopes are ignored. |
| Tokens | Access tokens: 1 hour. Refresh tokens: 30 days, single use, rotated on every refresh; using one twice disconnects the app. Revocation ([RFC 7009](https://www.rfc-editor.org/rfc/rfc7009)) at `/oauth/revoke`. |

A person approves each app in the dashboard, for one organization. Owners and admins only. Apps are listed, and can be disconnected, in **Settings**, **Connected apps**.

## Safety model

- **Everything goes through the Rowsafe API**, with the same API key, checks, plan limits and audit log as the CLI. Every change a tool makes or asks for is in `rowsafe audit`, attributed to the key or app.
- **Tools can only do what the API can do.** They queue the fixed agent tasks and change schedules. Nothing runs commands or SQL on production or reads backup contents: Rowsafe can't do those at all.
- **Changes to production are requests a person approves.** Restoring, bringing rows back, rewinding, restarting, applying fixes, changing settings, updates and upgrades, standbys, moves, pooling, security fixes and the rest go through `request_change`. It files a request and returns a link to it in the dashboard; it never makes the change. Nothing runs until an owner or admin signed in to the dashboard approves it, and API keys and assistants can never approve, not even their own requests. On approve, Rowsafe makes the dashboard's own API call as that person, with the same checks and confirmations, and restarts still run only on servers where root allowed them at install. See [Approvals](/docs/guides/approvals).
- **Read-only unless you say otherwise.** `rowsafe mcp` registers read tools only, plus the copy tools, which never touch production (`preview_migration` runs SQL on a fresh copy as a regular role; `create_safe_copy` makes masked copies only, within your plan's limit). `--allow-restore-points` adds only `create_restore_point`. `--allow-writes` adds the actions that don't touch production, `request_change` and `cancel_approval`.
- **No secrets through assistants.** Passwords are set by people in the dashboard: new database users, password resets, restored copies, and safe copies made through the remote endpoint. Bucket keys and the passphrase never leave your server. Outputs are capped in size.
- **Not exposed at all:** enrollment tokens, API keys, removing hosts, members and roles, plan changes, agent update settings, and what root allowed on a server.
- **Annotations.** Read tools are marked read-only. `update_schedule` (lowering retention deletes old backups) and `delete_safe_copy` are marked destructive, so clients that confirm destructive calls will ask you.

## Tools

**Read** tools are always there. **Marks** needs `--allow-restore-points` (or **Save Marks**). **Copies** never touch production: `rowsafe mcp` and API keys always get them; signed-in apps need **Act for you**. **Write** needs `--allow-writes`, a read-write API key, or **Act for you**.

### Is it safe? Marks and Rewind

| Tool | Access | What it does |
|---|---|---|
| `safety_check` | read | Is the database [protected](/docs/concepts/protection-status) right now? |
| `create_restore_point` | Marks | Set a Mark: name this moment, and wait until it is in your bucket. |
| `list_restore_points` | read | Marks (restore points) with their status and the backup to restore from. |
| `rewind_window` | read | How far back the database can be rewound: the earliest and latest second, the newest Marks, a restored copy if there is one, data kept aside by a rewind, and whether the whole database can be rewound on its server. |
| `find_moment` | read | [Find the moment](/docs/guides/find-the-moment): when rows were deleted or changed, or a table emptied or dropped, with the exact time and the point just before it. Also lists earlier searches. |

### Fleet, backups and tasks

| Tool | Access | What it does |
|---|---|---|
| `fleet_health` | read | Every problem in the fleet, worst first, each with the next step. |
| `get_org` | read | Plan, limits and usage. |
| `list_hosts` | read | Hosts, online or not, agent version, update channel and state. |
| `list_databases` | read | Databases with a health summary. |
| `get_database` | read | One database in depth: settings, schedules, WAL, recent backups, Proof runs, tasks and problems. |
| `list_backups` | read | Backups, newest first. |
| `list_drills` | read | Proof runs (restore tests) with failures and warnings. |
| `list_tasks` | read | Tasks, filtered by database, status and type. |
| `get_task` | read | One task with its result, the end of its log and the next step. |
| `backup_storage` | read | What the backups take in each bucket, the estimated monthly cost, and whether a [second copy](/docs/guides/second-copy) exists and is up to date. |
| `files_status` | read | The folders backed up with a database (uploads, media): status, last snapshot, size, how far back; with `at`, the files backup nearest that time. |

| `live_activity` | read | What a database runs right now, longest first, and lock chains: which session blocks which. It ends nothing. |
| `database_metrics` | read | A database's and its server's numbers over time (CPU, memory, load, disk, connections, transactions, cache hits, locks, lag, size): min, average, max and the latest value, or the data points. |

| Tool | Access | What it does |
|---|---|---|

| `update_schedule` | write, destructive | Change the schedules (UTC cron) and `retention_full`. |

| `ack_alert` | write | Acknowledge a firing alert: no more repeat notifications. |
| `dismiss_recommendation` | write | Set a recommendation aside with a reason, or bring it back (`undo`). |
| `run_index_check` | write | Look for missing indexes now, tested on a copy restored on the database's server. |
| `check_upgrade` | write | The read-only preflight for a major upgrade: what blocks it and which modes are possible. |
| `rehearse_upgrade` | write | Upgrade a throwaway copy, check it and measure the downtime, then delete it. A passed rehearsal allows the real upgrade. |
| `run_security_check` | write | Read the security settings again now, and check the port from the internet again. |
| `backup_files` | write | Back up the folders that go with a database now, optionally tagged with a name; with `check`, run the files Proof instead. |

| Tool | Access | What it does |
|---|---|---|
| `request_change` | write | Ask a person to approve a change to production: `action`, `database`, `params` and your `reason`. Returns the request with its link in the dashboard; it never makes the change. |
| `describe_change` | read | The actions you can ask for, by group, with their risk and the JSON schema of their params. |
| `get_approval` | read | One request: pending, approved (with the tasks it started), failed, denied (with the person's note), expired or cancelled. Can wait for a decision. |
| `list_approvals` | read | Requests, newest first. |

## Troubleshooting

- **"not logged in"** in the client's MCP log: run `rowsafe login`, or set `ROWSAFE_API_KEY` in the server's environment.
- **Tools missing:** write tools and `request_change` only appear with `--allow-writes`, Marks with `--allow-restore-points`. Restart the client after changing flags. A signed-in app gets them only if you allowed **Act for you** (and **Save Marks**); connect it again to change that.
- **`forbidden (403): This API key is read-only.`:** the key can only read.
- **A request stays pending:** an owner or admin approves it in the dashboard, under **Approvals**. It expires after 24 hours.
- **A 402 error:** a plan limit is reached. `get_org` shows your usage.
- **Smoke test** without a client:

  ```sh
  printf '%s\n' \
    '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"0"}}}' \
    '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
    '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | (cat; sleep 2) | rowsafe mcp
  ```
