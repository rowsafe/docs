Rowsafe speaks the [Model Context Protocol](https://modelcontextprotocol.io). AI assistants can check your fleet ("is everything backed up?", "why did this alert fire?") and, when you allow it, set Marks (restore points) or queue backups and Proof runs. The MCP tools are part of [Guard](/docs/guides/ai-agents), the safety net for AI agents.

| | Transport | Credentials | Write tools |
|---|---|---|---|
| `rowsafe mcp` | stdio, on your machine | The CLI's login, or `ROWSAFE_API_KEY` | Off by default. `--allow-restore-points` or `--allow-writes`. |
| `https://api.rowsafe.sh/mcp` | Streamable HTTP | **Sign in with Rowsafe** (OAuth), or `Authorization: Bearer rsk_...` | Signed-in apps: `create_restore_point` only, if you allowed Marks. API keys: always listed; a read-only key can't use them. |

For the safety-net workflow with coding agents, see [Use Rowsafe with AI agents](/docs/guides/ai-agents). To add Rowsafe to ChatGPT, Claude, Cursor, VS Code, Codex or Windsurf without an API key, see [Connect AI apps](/docs/guides/connect-ai-apps).

## Set up

<Tabs items={["Claude Code", "Claude Desktop", "Remote endpoint"]}>
<Tab value="Claude Code">

Log in with the CLI first (`rowsafe login`), then pick a mode:

```sh
# Read-only
claude mcp add rowsafe -- rowsafe mcp

# Read-only, plus Marks (what the Claude Code plugin uses)
claude mcp add rowsafe -- rowsafe mcp --allow-restore-points

# Everything: backups, Proof, verification, adoption, schedules
claude mcp add rowsafe -- rowsafe mcp --allow-writes

# A specific key instead of your login, in every project
claude mcp add --scope user rowsafe -e ROWSAFE_API_KEY=rsk_... -- rowsafe mcp
```

`--scope project` writes `.mcp.json` into your repository for everyone: don't put a key in it. Use the stdio form (each developer's own login) there.

</Tab>
<Tab value="Claude Desktop">

Claude Desktop runs local servers from its config file: `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS, `%APPDATA%\Claude\claude_desktop_config.json` on Windows (**Settings**, **Developer**, **Edit Config**).

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "rowsafe": {
      "command": "/usr/local/bin/rowsafe",
      "args": ["mcp"],
      "env": {
        "ROWSAFE_API_KEY": "rsk_..."
      }
    }
  }
}
```

Use the absolute path of `rowsafe` (`which rowsafe`): Desktop doesn't use your shell's `PATH`. Add `"--allow-restore-points"` or `"--allow-writes"` to `args` for write tools. Restart Claude Desktop afterwards.

Or use a remote connector instead (**Settings**, **Connectors**, **Add custom connector**, `https://api.rowsafe.sh/mcp`): you sign in with Rowsafe, no key or local binary needed. See [Connect AI apps](/docs/guides/connect-ai-apps).

</Tab>
<Tab value="Remote endpoint">

No local binary needed. Sign in with Rowsafe (run `/mcp` in Claude Code, then **Authenticate**):

```sh
claude mcp add --transport http rowsafe https://api.rowsafe.sh/mcp
```

Or with an API key, for CI and clients without OAuth:

```sh
claude mcp add --transport http rowsafe https://api.rowsafe.sh/mcp --header "Authorization: Bearer rsk_..."
```

- Every request needs an OAuth access token or an API key. Use a [read-only key](/docs/guides/teams#api-keys) (`rowsafe api-keys create NAME --read-only`) for an assistant that must never change anything.
- The endpoint is stateless and answers with plain JSON.
- Tool calls wait at most 45 seconds.

</Tab>
</Tabs>

## Sign in with Rowsafe (OAuth)

The remote endpoint is an OAuth 2.1 protected resource, following the [MCP authorization specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) (2026-07-28). MCP clients discover everything from the first `401`; you only give them the URL. See [Connect AI apps](/docs/guides/connect-ai-apps) for each client.

| | |
|---|---|
| Protected resource metadata ([RFC 9728](https://www.rfc-editor.org/rfc/rfc9728)) | `https://api.rowsafe.sh/.well-known/oauth-protected-resource/mcp`, named in `WWW-Authenticate` on every `401` |
| Authorization server metadata ([RFC 8414](https://www.rfc-editor.org/rfc/rfc8414)) | `https://api.rowsafe.sh/.well-known/oauth-authorization-server` (issuer `https://api.rowsafe.sh`) |
| Client registration | Client ID metadata documents (an HTTPS `client_id`), or dynamic registration ([RFC 7591](https://www.rfc-editor.org/rfc/rfc7591)) at `/oauth/register`. Clients are public: no client secret. |
| Grant | Authorization code with PKCE, `S256` only. The response carries `iss` ([RFC 9207](https://www.rfc-editor.org/rfc/rfc9207)). |
| Redirect URIs | Exact match. Accepted: ChatGPT's, Claude's, VS Code's and Cursor's published callbacks, and loopback (`http://127.0.0.1`, `http://[::1]`, `http://localhost`, any port). |
| Resource ([RFC 8707](https://www.rfc-editor.org/rfc/rfc8707)) | `https://api.rowsafe.sh/mcp`. Tokens work on `/mcp` only. |
| Scopes | `rowsafe:read` (always), `rowsafe:marks` (optional: adds `create_restore_point`). `offline_access` is accepted; other scopes are ignored. |
| Tokens | Access tokens: 1 hour. Refresh tokens: 30 days, single use, rotated on every refresh; using one twice disconnects the app. Revocation ([RFC 7009](https://www.rfc-editor.org/rfc/rfc7009)) at `/oauth/revoke`. |

A person approves each app in the dashboard, for one organization. Owners and admins only. Apps are listed, and can be disconnected, in **Settings**, **Connected apps**.

## Safety model

- **Everything goes through the Rowsafe API**, with the same API key, checks, plan limits and audit log as the CLI. Every change a tool makes is in `rowsafe audit`, attributed to the key.
- **Tools can only do what the API can do.** They queue the fixed agent tasks and change schedules. Nothing runs commands or SQL, restores a backup or reads backup contents: Rowsafe can't do those at all.
- **No restarts.** No tool restarts PostgreSQL, even on a server where restarts from the dashboard are allowed. Only a person can, in the dashboard or with `rowsafe restart`.
- **Read-only unless you say otherwise.** `rowsafe mcp` registers read tools only, plus the copy tools, which never touch production (`preview_migration` runs SQL on a fresh copy as a regular role; `create_safe_copy` makes masked copies only, within your plan's limit). `--allow-restore-points` adds only `create_restore_point`. `--allow-writes` adds every write tool.
- **Not exposed at all:** enrollment tokens, API keys, removing hosts or databases, plan changes, and agent update settings.
- **`apply_adoption` needs your approval.** It refuses unless `confirm` is the database's exact name and a read-only plan succeeded. Its description tells the model to show you the plan and ask first, and never to pass `force` unless you asked.
- **Annotations.** Read tools are marked read-only. `apply_adoption` and `update_schedule` (lowering retention deletes old backups) are marked destructive, so clients that confirm destructive calls will ask you.
- **No secrets in output.** Bucket keys and the passphrase never leave your server. Outputs are capped in size.

## Tools

| Tool | Access | What it does |
|---|---|---|
| `fleet_health` | read | Every problem in the fleet, worst first, each with the next step. |
| `get_org` | read | Plan, limits and usage. |
| `list_hosts` | read | Hosts, online or not, agent version, update channel and state. |
| `list_databases` | read | Databases with a health summary. |
| `get_database` | read | One database in depth: settings, schedules, WAL, recent backups, Proof runs, tasks and problems. |
| `list_backups` | read | Backups, newest first. |
| `list_drills` | read | Proof runs (restore tests) with failures and warnings. |
| `list_tasks` | read | Tasks, filtered by database, status and type. |
| `get_task` | read | One task with its result, the end of its log and the next step. |
| `database_health` | read | Pulse: health score (0-100) and plain-language findings with what to do. Without a database, every database's score. |
| `database_insights` | read | Largest tables, unused and duplicate indexes, estimated bloat, dead rows, tables that may need an index. |
| `query_trends` | read | Queries that took the most time in a range, and which got slower; or one query over time. |
| `safety_check` | read | Is the database [protected](/docs/concepts/protection-status) right now? |
| `backup_storage` | read | What the backups take in each bucket, the estimated monthly cost, and whether a [second copy](/docs/guides/second-copy) exists and is up to date. |
| `list_restore_points` | read | Marks (restore points) with their status and the backup to restore from. |
| `find_moment` | read | [Find the moment](/docs/guides/find-the-moment): when rows were deleted or changed, or a table emptied or dropped, with the exact time and the point just before it. |
| `create_restore_point` | restore points | Set a Mark: name this moment, and wait until it is in your bucket. |
| `preview_migration` | read | [Preview a migration](/docs/guides/preview-migrations): run its SQL on a fresh copy of the database (never production) and get a verdict with suggestions. |
| `get_preview` | read | A preview's result, when it wasn't done within the wait. |
| `create_safe_copy` | copies | Make a masked [safe copy](/docs/guides/safe-copies). Always masked. Locally the password is made on your machine and returned once; on the remote endpoint the copy starts without a password and the tool returns a dashboard link where you set it. |
| `list_safe_copies` | read | Safe copies, their status and where to connect. |
| `delete_safe_copy` | copies | Delete a safe copy. |
| `plan_adoption` | write | Register a database on a host and produce a read-only plan, or plan again. |
| `apply_adoption` | write, destructive | Apply the plan. Needs `confirm: "<database name>"`. |
| `verify_database` | write | Prove WAL reaches the bucket; activates the schedules. |
| `run_backup` | write | Queue a `full`, `diff` or `incr` backup. |
| `run_drill` | write | Queue a Proof run (restore test). |
| `update_schedule` | write, destructive | Change the schedules (UTC cron) and `retention_full`. |

Apps signed in with Rowsafe (OAuth) can only read and set Marks, so they don't get `preview_migration`, `create_safe_copy` or `delete_safe_copy`. Use the local `rowsafe mcp`, or the remote endpoint with an API key, for those.

There is also one prompt, `incident_triage`: check the fleet, read the evidence behind each problem, and propose next steps without changing anything.

## Troubleshooting

- **"not logged in"** in the client's MCP log: run `rowsafe login`, or set `ROWSAFE_API_KEY` in the server's environment.
- **Tools missing:** write tools only appear with `--allow-writes`, Marks with `--allow-restore-points`. Restart the client after changing flags.
- **`forbidden (403): This API key is read-only.`:** the key can only read.
- **A 402 error:** a plan limit is reached. `get_org` shows your usage.
- **Smoke test** without a client:

  ```sh
  printf '%s\n' \
    '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"0"}}}' \
    '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
    '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | (cat; sleep 2) | rowsafe mcp
  ```
